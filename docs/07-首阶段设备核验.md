# 首阶段设备核验

**本文件是未来 P0 的操作计划，所有设备项目尚未执行。** 本次没有运行 adb、连接手表、安装应用或修改手表设置。

## 1. 核验目的

把“OPPO Watch X2 普通安卓圆表”转换为可以指导开发的实际参数。当前唯一已确认的设备信息来自用户描述；同名设备的地区、固件或销售渠道可能影响安装与系统能力，不能从产品名称直接推断 API、Wear OS 或 GMS。

## 3. 未来只读采集步骤

在用户已经连接并授权调试的设备上操作。先核对序列号，避免把手机误当手表。以下 PowerShell 命令只是文档示例，尚未执行。

```powershell
adb devices -l
$watchSerial = '替换为目标手表序列号'
adb -s $watchSerial shell getprop ro.product.model
adb -s $watchSerial shell getprop ro.product.name
adb -s $watchSerial shell getprop ro.build.display.id
adb -s $watchSerial shell getprop ro.build.version.release
adb -s $watchSerial shell getprop ro.build.version.sdk
adb -s $watchSerial shell getprop ro.product.cpu.abilist
adb -s $watchSerial shell wm size
adb -s $watchSerial shell wm density
adb -s $watchSerial shell settings get system font_scale
adb -s $watchSerial shell pm list features
adb -s $watchSerial shell pm list packages com.google.android.gms
adb -s $watchSerial shell dumpsys webviewupdate
adb -s $watchSerial shell dumpsys input
adb -s $watchSerial shell df -h /data
```

`wm size/density` 在不追加数值时用于查询；本计划不修改它们。若厂商禁用命令或权限不足，记录失败并从系统“关于”和显示设置补充，不要求 root。GMS 包存在不等于服务可用，也不自动证明设备适合 Wear OS Data Layer。

网络和音频问题可在后续按需只读查看 `dumpsys connectivity`、`dumpsys audio`、`dumpsys power`，结果留在本地，记录中只保留诊断所需字段，不把包含设备/网络标识的完整输出直接发布。

## 4. 安装与运行验证（未来执行）

1. 确认开发模式与可用安装方式，记录普通签名 APK 是否可安装、启动器是否显示入口、触摸返回是否正常。
2. 用后续制作的最小播放样例验证目标 API 和基础 Compose/Media3 组合。先测试合法本地音频，再测试受控 HTTPS 音频，区分解码与网络问题。
3. 配对已有蓝牙耳机，确认实际音频从耳机输出；断开时应暂停，记录系统是否尝试转扬声器。
4. 熄屏并退出页面，连续播放至少 30 分钟；记录当时的电源模式、应用权限和系统设置。若只能保持亮屏才能播放，则不算通过。
5. 测试手机离线、Wi-Fi 直连、可用时蜂窝和手机代理网络，分别确认元数据请求和音频下载；不要仅依据连接图标判断。
6. 记录表冠旋转是否能进入应用、普通返回是否可用、媒体按键是否到达会话；所有主流程仍需触控可完成。

本步骤涉及未来安装和测试，当前只建立清单；不提前生成、安装或执行样例。

## 5. 登录验证记录

| 实验 | 记录内容 | 选择依据 |
| --- | --- | --- |
| 原生 QR/EAPI | 请求成功/失败、状态变化、账号校验结果、耗时；不记录原始 key/Cookie | 在目标设备上稳定可用时优先 |
| Android WebView 桥接 | provider 版本、页面加载、二维码生成、Cookie 获取及退出清理 | 只有设备存在可用 WebView 且原生路径受阻才评估 |
| 账号持久化 | 重启应用/设备、系统清理后是否保留；密钥异常处理 | 成功会话应安全保存，异常需明确重登 |
| 网络风控/限流 | HTTP/业务错误码、重试窗口、网络类型 | 有限退避，不能无限切换参数重试 |

如两条独立登录路线都失败，记录在线路径阻断原因，评估手机辅助配对或其他可行登录路径的成本；不得在计划状态下标注“扫码已支持”。已独立验证的共享基础和本地路径仍可推进，不以登录失败阻断本地工作；首版仍须在线/本地门槛全部通过，不能静默改成仅本地发布。

## 6. DEV-005：本地文件访问与格式探针（未来执行）

首个公开 `0.1.0` 已包含 P2-L 本地音乐，P0 安排探针，进入 P2-L 前必须证明至少一条面向用户的文件访问路径可行；共享 P1 可以在设备/安装/音频条件已验证后推进，不必等待另一条业务路径的阻断解除。探针使用未来云端构建的最小样例与用户允许的一次性音频样本；本次未构建、安装或运行。官方依据与完整设计见 [17 本地计划](17-本地音乐功能与实施计划.md)。

| 探针 | 操作和应留证据 | 未通过时的处理 |
| --- | --- | --- |
| 文件进入手表 | 记录用户已有文件或系统文件管理器等实际可用放置方式、可读范围与空间；内部测试音频不能冒充用户访问路径 | 无可用路径即阻断，不把未来 Wi-Fi 传歌当已解决 |
| MediaStore | 按实际 API/target 申请所需音频读取权限；查询少量已知样本，核验音频 URI、元数据、打开与播放，区分空集合/拒绝/不支持 | 拒绝保持稳定错误与旧索引；评估已经证实存在的其他授权入口 |
| 文件选择器 / SAF 树 | 核验 `ACTION_OPEN_DOCUMENT` 与 `ACTION_OPEN_DOCUMENT_TREE` 是否有处理器、能否用触控完成选择；分别记录 provider、范围和返回的读/持久授权标志 | 无处理器就明确不提供该入口；不硬编码绝对路径或用 root/全盘访问绕过 |
| 持久化与重启 | 仅在返回授权允许时获取持久 URI 读取权限；重启应用/设备后再次打开；记录 provider 对文档身份和权限的实际行为 | 临时授权不冒充持久授权；若需要持久副本且源可合法读取，单独显式导入并先检查空间 |
| 拒绝、取消、撤销与重授 | 首次拒绝/取消、扫描中撤销、播放前撤销，再从同一来源重授并重扫；旧库/收藏/列表/历史保留 | 稳定错误，限制重试；不能把失败当空扫描清库，不能要求登录来恢复本地访问 |
| 原文件移动/缺失 | 在系统文件管理器使用一次性样本模拟移动/删除，核验 URI 是否改变、是否可重新定位和重关联 | 保留身份与不可用原因；不向产品增加外部原文件物理删除 UI |
| 必要导入副本 | 只在无法持久引用等实际需要时测试用户确认后的复制，检查独立配额/保留空间、取消及低空间 | 不自动复制整库；未完成副本不入可播库，清理临时副本不碰原件 |
| 容器＋编码矩阵 | 分别记录 MP3、AAC/ADTS、M4A 中 AAC、原生 FLAC、WAV 中 PCM、Ogg 中 Vorbis/Opus 等样本的编码/采样率/位深/声道、文件摘要与来源；测试首声/seek/时长/结束 | 成功只证明该组合；坏文件/不支持格式给稳定错误，不引入额外解码器或 DRM 解密 |
| 完全本地路径 | 无在线账号、关闭 Wi-Fi/蜂窝/手机网络代理；保持蓝牙耳机输出；记录无账号/HTTP/DNS/封面歌词补全请求 | 选择器若仅有依赖网络的 provider，不算已验证离线来源 |

能力结论写明“MediaStore 可用”“文件选择可用”“目录授权可用”“需要显式导入副本”各自的证据和限制，不要求固件实现所有入口，也不把某条入口失败说成已被绕过。所有支持入口都须覆盖拒绝、撤权、恢复，且至少一条能让用户实际添加并持久使用设备音频。若不存在，P0 本地门槛未通过，先记录阻断并重新评估范围/工期，不继续宣称首版可交付。

P0 的最小 30 分钟后台试验只是探针；首版仍要按 [14 性能预算](14-性能优先与资源预算.md) 完成在线至少 60 分钟、本地至少 120 分钟熄屏测试，以及 [06](06-测试验收与风险.md) T-23–31、[15](15-界面设计与视觉验收.md) 界面和 [16](16-代码规范与可读性.md) 代码验收。DEV-005 工时已计入本地新增 8–12 人日，不在原 P0 估算上重复加算。

## 7. P0 输出与决策

应形成设备能力表、安装/音频验证记录、登录路线结论、本地来源/授权/格式矩阵和初始工具链清单，并回答：

- 当前固件是否支持首发产品形态？
- 是否能在无 GMS 条件下独立完成账号与播放主流程？
- 是否存在可持久使用的合法本地访问路径；无账号、无网络时能否添加/浏览/播放？哪些来源和容器＋编码组合仍未验证？
- 哪些模式能稳定熄屏播放，哪些模式明确不支持？
- 实际 minSdk、ABI 和 UI 的 dp 测试范围如何选？
- P1 是否可以开始；若不可以，最小范围调整是什么？

只有这些问题具备证据后，才把估算转为实际开工排期。
