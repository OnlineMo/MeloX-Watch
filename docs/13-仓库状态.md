## 当前发布规则

- 普通贡献者 PR 不得改 `version.properties`；OnlineMo 的版本 PR 可以修改，但格式和版本名/code 相对 base 与发布历史的递增必须通过检查。
- 所有 PR 均不得改 workflows/actions；通过 Actions Issue 申请所有者维护。
- OnlineMo 可从网页选择 main、输入 `x.y.z` 触发 Owner release；正式 `versionCode = max(main 完整可达提交数 + 1, 历次发布最大 code + 1)`，加 1 包含发版版本提交，拒绝浅克隆。
- 发版只创建临时 detached 版本提交和新 tag，不增加发布分支、不回写两个开发分支。没有长期仓库写入凭据。
- 现有Release是验收前置后构建/立即发布的单阶段实现，不能生成待验正式候选，也不能发布已验同一个APK；目标流程已由终审改为候选→验收→同包发布，**CI-01–04完成前不得真实发版**。

## 尚待完成的边界

当前私有仓库不能启用 required checks、管理员同样受限和 tag 禁改删规则，因此 **CI 失败不等于 GitHub 已强制禁止合并或直接推送**。保持私有及唯一所有者写权限；公开前依照 12 文档完成套餐升级，或由所有者另行批准公开转换后立即设置规则。没有自动升级套餐或公开仓库。

用户已明确要求记住公开后的保护配置。执行公开流程的人/agent 必须完成 [GOV-PUBLIC-01 操作清单](10-仓库治理与发布.md)，读回 main/contribution 的完整规则并记录证据；全部通过后更新本页和实际发布门槛，不能只移除网页警告就视为完成。
