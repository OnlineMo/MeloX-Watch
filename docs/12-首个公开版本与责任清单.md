# 首个公开版本与责任清单

当前应用仍处于规划阶段，Android 工程尚未实施，P0–P5 均未完成，没有 APK 或设备测试结果。仓库保持私有，只有 OnlineMo 有写权限。已记录的 rulesets GET 实际返回 403，需升级 GitHub Pro 或改为公开才能启用所需保护；当前没有强制分支/tag 保护。本文规定验收要求，实际配置与限制见 [仓库状态](13-仓库状态.md)，不能把文档、证书生成或规划检查当作应用可发布的证据。

## 1. 版本边界

| 里程碑 | 必须完成 | 可见性和发布 |
| --- | --- | --- |
| 当前规划/基础设施 | 开发计划、治理约定与云端接入准备 | 私有；无应用发布，开发版本 0.0.0 / 0 |
| 内部在线 MVP | P0–P3 | 私有候选产物与设备验收，修复阻断问题 |
| 首个公开测试版 v0.1.0 | P0–P3 + 全部首次公开门槛、证据及用户明确批准 | 发布为 prerelease；公开操作另需用户批准 |
| 日常使用正式版 v1.0.0 | P0–P5 + 相应验收与发布门槛 | 增加持久下载、离线库、长时/恢复测试及完整发布材料 |

首个公开测试版允许暂不具备离线下载，但 README 和 Release 必须明确范围，不能描述为完整 1.0。即使把首次公开推迟到 P5，默认首个公开版本仍为 0.1.0 prerelease；调整产品与版本计划需另获用户确认。

当前 **0.0.0 / 0** 仅为初始占位，没有永久固定值或字节校验要求。contribution/main 拒绝非 OnlineMo 作者的版本文件变更；OnlineMo 的版本 PR 自动校验精确 `x.y.z`（无 `v`、后缀、前导零）与不超过 2100000000 的整数 versionCode，两者都必须严格高于 base 和全部发布 tag。普通 Debug 使用 `.dev` 与独立稳定 Debug 证书，依靠 source SHA、build SHA 和 Actions run 识别产物；PR 使用临时证书且无 secrets。

发布在临时 runner 中从已审阅 main SHA 创建 detached 快照，仅改版本文件并打 tag，**不创建额外发布分支**。请求版本须严格高于所有精确发布 tag，且不低于 main 候选版本；相同时沿用 main code（须高于全部已发布 code），更高版本取 `max(最高已发布 code + 1, main code + 1)`，无 tag 时最高已发布 code 为 0，并遵守上述格式及 code 上限。仅使用所有者手动触发运行的短期 `GITHUB_TOKEN` 推送新 tag、发布 Release，不回写 main/contribution、不合回快照、不使用 deploy keys。完整约定见 [仓库治理与发布](10-仓库治理与发布.md)。

## 2. 首次公开与发布门槛

首个公开应用版本必须满足以下全部门槛；当前没有应用、APK 或实机证据，不能提前标为通过。

- [ ] P0：实际 Watch X2 型号/API/ABI、安装、网络、扫码和熄屏播放验证完成。
- [ ] P1：精简工程、媒体服务、焦点、耳机断开及队列恢复完成。
- [ ] P2：真实登录、喜欢/歌单/日推、歌曲搜索分页和在线播放闭环完成。
- [ ] P3：圆屏三页、逐行歌词、返回/表冠降级、错误反馈完成。
- [ ] 云端对待发布的精确快照完成单测、lint、Release 编译，读取 APK 实际 versionName/versionCode、正式包名并校验签名指纹和 SHA-256；保留 source/build SHA、run 和产物证据。
- [ ] Watch X2 使用该云端产物完成安装、扫码、播放、切歌、耳机断开和至少 60 分钟在线熄屏测试，并提交脱敏报告。
- [ ] 无已知阻断崩溃、凭证泄漏或意外外放；未完成能力和设备限制写明。
- [ ] 复用代码有固定 SHA、来源与许可记录；所分发字体/图标/其他资源有清晰来源。
- [ ] 本项目全部历史、文件、Issue/PR 材料和产物检查无真实邮箱、凭据、签名私钥、私有恢复仓库标识及 AI 协作者署名。独立私有恢复仓库不在公开范围内。
- [ ] main/contribution 保护实际生效：必须 PR，`cloud-gate`/`pr-policy` 绑定预期 GitHub App，strict 要求最新状态，禁止强推/删除，管理员受约束且无绕过；批准审阅数为 0，所有者人工审阅并独自合并。
- [ ] tag 更新/删除被禁止，创建限写入者；只有 OnlineMo 与其手动触发发布的临时 token 有所需内容写权限，不授予公开贡献者写权限。所有者专属发布及仅新增快照 tag 的行为经验证。
- [ ] 可信 `pull_request_target` 检查仅用固定 base SHA 的策略与只读 API，拒绝非 OnlineMo 作者的版本文件变更，对 OnlineMo 的版本 PR 自动校验格式及相对 base/全部发布 tag 的双项递增；Actions 路径仍拒绝所有 PR（包括所有者）的新增、修改、删除和重命名，不执行 PR 代码。Actions Issue 与所有者直接认证维护、必要时恢复保护并留档的方式明确。
- [ ] 安装、云端构建、反馈指南、首版说明、仓库级签名 secrets 与恢复验证完成；证书和 APK 指纹与 [.ci/signing-certificates.json](../.ci/signing-certificates.json) 一致。
- [ ] OnlineMo 审阅所有证据，明确批准公开仓库和发布 0.1.0 prerelease。

`.ci/release-readiness.json` 必须对应真实验收记录，不能为了让工作流通过而提前勾选；只有所有者根据证据更新。设备报告路径须指向已提交的 docs 文件。发布当次重新运行构建检查，不用过往 run 替代；重建产物若与已测 APK 的校验值不一致，必须重新完成对应产物的验收，不把旧设备报告直接套用。

签名证书已独立生成：Release/Debug 均为 RSA 3072、SHA-256、30 年有效期；CN 分别为 `OnlineMo MeloX Watch Release` / `OnlineMo MeloX Watch Debug`，O 为 `OnlineMo`，OU 为 `MeloX Watch`，没有 C/ST/L/email。生成证书与固定指纹不等于云端配置完成。当前私有套餐的 environments 可能不支持，采用仓库级 Actions secrets，配置和验证状态仍以 13 文档为准。

用户已明确授权将 p12、明文密码及恢复元数据保存于**独立且永久私有的恢复仓库**。恢复仓库必须关闭 Actions、没有协作者；本项目公开时仍不得公开它。公开材料只描述通用恢复方式，不记录密码、仓库名称或地址。

## 3. 你与开发者/agent 分工

| 工作 | 开发者 / agent | 你（OnlineMo） |
| --- | --- | --- |
| 范围和计划 | 整理任务、依赖、风险、验收 | 确认产品取舍和优先级 |
| 设备参数 | 提供读取步骤、整理结果、据此适配 | 提供手表可用测试条件，必要时授权调试 |
| 账号 | 实现扫码/会话逻辑，使用脱敏样本 | 在自己手机扫码，不把 Cookie/密码发给开发者或写入本项目 |
| 代码与复用 | 按固定上游提取、重写边界、测试和文档 | 审阅阶段结果 |
| 云端构建 | 提交并查看 Actions、修复失败、整理 APK/校验值 | 首次账号权限授权、必要的费用/配额选择 |
| 实机验证 | 准备测试清单；设备可连接时执行已授权操作并整理日志 | 无远程设备通道时安装云端 APK，验证耳机、熄屏、圆屏和体感 |
| Actions 维护 | 通过 Actions Issue 提供变更与验证材料 | 审阅后直接认证维护；必要的保护调整立即恢复并记录 |
| 公开前检查 | 检查历史/资源/文档/规则，核对证据并列出限制 | 决定套餐/可见性，确认可以公开；保存并验证私有签名恢复材料 |
| 发版 | 准备快照和材料，执行已授权的云端验证与发布流程 | 唯一有权决定和触发发布，人工审阅后合并 PR |

如果设备暂时不可用，已获授权的代码工作可以推进，但实机门槛保持未通过，不以模拟器结果替代。当前文档工作不授权启动 Android 实施。你不需要手写客户端或在本地配置 Android 编译环境。

## 4. 公开操作顺序

先在私有阶段完成 P0–P3、候选云端产物与设备验收，整理精确提交、校验值和首版说明；审查整个已有历史。候选构建按发布快照规则验证，不提前推送正式 tag；若源码、版本分配或产物变化，需重新核验对应证据。

公开前解决规则可用性。升级 GitHub Pro 可在私有阶段启用并验证保护；若选择通过公开解决套餐限制，须在其他门槛和证据完成后，由用户明确批准分步操作：改变可见性、立即启用并核验全部保护，最后才发布首版。保护未验证前不发布、不开放贡献者写权限。自动工作流不自行改变可见性。

完成全部门槛和明确授权后，仅由 OnlineMo 在网页 **Actions → Owner release → Run workflow** 选择 main 手动触发，无需本地电脑；核验 detached 快照及对应产物，只创建新的 v0.1.0 tag 和 prerelease。若 tag 已创建而 Release 上传失败，恢复该 tag 对应的同一 Release，不删除、覆盖或重用版本；发布不回写开发分支。网页发布可行性的讨论不构成发布授权，本次未执行发布。

即使未来规则生效，所有者仍可重新配置；CI 不能单独阻止管理员直接推送。当前 403 与保护缺失必须如实保留在状态记录中，不能把本清单当作已通过的验收报告。
