# 首个公开版本与责任清单

终审：2026-11-11。当前应用与所有设备验收未开始，仓库私有。CI-01–04尚需建设，**现有单阶段Owner release不能直接用来生成首个待验候选或发布**。完整问题与开工顺序见 [20](20-终审结论与开工清单.md)，真实历史状态见 [13](13-仓库状态.md)。

产品面向Android智能手表。首个实际验收设备是用户现有Watch X2，保留该设备的实测门槛不构成型号限制；圆/方形窗口按能力适配，兼容清单记录每台的真实证据。发布不能写“仅支持OPPO”或“全部手表已适配”，除非实际范围/证据支持。

开发前置源码通过PR #16建设，工作流维护另在Issue #15，源码整合不表示候选/发布流程已启用。继续建设前核对真实PR/提交、[建设记录](ci/CI-01–04建设记录.md)和13，保留全量本地规划及尚未验收的基础设施任务。

本地能力从首版就必须无账号、无互联网可用；在线“我喜欢/歌单”只读，本地收藏/歌单可编辑。Meting由用户填地址，默认关闭，初始协议可控验证不承诺所有歌曲解锁。未来音源仅保留通用接口，不预定下一家平台。功能范围以02/17/19/21为准，任务依赖见05；不做工期或工作量估算。离线零请求指核心路径；用户显式开启的补全、更新、传输和手机管理另验，不因此删掉这些必做功能。

发布版本名、提交计数code和仅tag快照规则见10。正式候选包名为计划的`io.github.onlinemo.meloxwatch`，Debug使用`.dev`与独立证书；不能将Debug包的设备结果无说明地覆盖到正式APK。

## 3. 你与开发者/agent的分工

| 工作 | 开发者/agent | OnlineMo |
| --- | --- | --- |
| CI/实现 | 按20/05修基础设施、实现、云端检查和资料；工作流修改走Issue维护 | 提供已有权限范围内的账号环境；必要的费用/套餐选择单独决定 |
| 设备与账号 | 提供可执行探针、样本和测试步骤，设备可连时执行已授权操作 | 提供现有手表/耳机、Android手机及可用调试条件；蓝牙歌词接收端按已选协议取得实证；扫码由自己完成，不上传Cookie |
| 性能/界面 | 建立可测基线、分析证据、实现合理降级，不编造数据 | 配合无法远程执行的操作、耗电长测；确认有证据的预算取舍 |
| 来源与恢复 | 整理实际复用和非敏感证据 | 保存独立签名备份；确认候选APK与风险/限制 |
| 公开与发版 | 先备齐候选、报告和具体操作；执行已授权的保护配置与发布 | 分别批准公开和发布，唯一决定/触发发布；不因使用AI协助增加AI署名 |

缺设备/扫码/服务时只阻断依赖项，继续其他工作并准确标记未测。你不需要本地安装Android编译环境或手写客户端。

## 4. 公开操作顺序

1. 私有阶段完成CI-01–04和功能收敛；OnlineMo在未来`prepare-candidate`生成手表与手机正式签名候选集，不推tag、不创建Release、不公开。
2. 下载并验证候选，用**同一候选集的原APK**完成手表、手机及协作的必需功能/性能/视觉测试。报告及readiness按10的允许路径提交，形成approval SHA；不以该文档提交重算code或重建APK。构建输入有变则作废候选重来。
3. 核对整个公开范围、候选可恢复备份与保护方案，再取得具体公开批准。仓库在当前私有套餐不能配置保护时，采用“批准公开→立即配置保护”的约定；用户若主动升级可提前配置，不自动付费。
4. **GOV-PUBLIC-01：公开后立即按10第6节配置main/contribution与v*保护，读回并验证，记录到13与候选报告。** 用户已经要求此步骤，无需再次提醒/重复授权同一配置；保护未通过不得发版或给额外贡献者写权限。独立恢复仓库仍私有。
5. OnlineMo批准指定候选后，在未来`publish-candidate`选择其run/attempt/artifact。流程读取审批与保护证据、复核最新标签和候选未失效，再发布原快照/原APK，不重编译或重签。
6. 验证tag、prerelease标志、资产完整性/哈希/签名、可下载性与两个分支保护；失败按10幂等恢复。发布成功只代表本版本，不自动开工P4或另一个音源。

候选准备、设备验收、公开、配置保护、发版是不同状态。任何一步失败保留证据并停止依赖步骤，不通过勾选boolean、放松保护或发布另一份未经测试的APK消除阻断。所有者仍能修改仓库设置，保护不是对所有者账号失窃的绝对保证。


## 5. 全量范围的完成判定

固定匿名源报告的13项“范围待明确”已经被用户全部纳入必做；参数/固件/协议待验证不等于范围可删。LP任务分组仅控制实施顺序。公开前逐条核对21的128行与256个AC：至少一个声明支持的实现路径跑通正常场景，同时验证错误和不支持环境。未实现、不具备设备证据、只有空入口或“不支持”提示的项保持未通过，阻断全量首版门槛。

当前coverage.json的`not_started`/`not_run`是实际起始状态。将来完成时关联具体commit、云端run和验收记录，不只改状态枚举。CI前置只配套迁移readiness的schema与历史键名，真值仍全部false；本轮不授权公开/发布。
