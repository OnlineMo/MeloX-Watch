# 首个公开版本与责任清单

当前应用仍处于规划阶段，Android 工程尚未实施，P0–P5（含新增 P2-L）均未完成，没有 APK 或设备测试结果。仓库保持私有，只有 OnlineMo 有写权限。已记录的 rulesets GET 实际返回 403，需升级 GitHub Pro 或改为公开才能启用所需保护；当前没有强制分支/tag 保护。本文规定验收要求，实际配置与限制见 [仓库状态](13-仓库状态.md)，不能把文档、证书生成或规划检查当作应用可发布的证据。

## 1. 版本边界

| 里程碑 | 必须完成 | 可见性和发布 |
| --- | --- | --- |
| 当前规划/基础设施 | 开发计划、治理约定与云端接入准备 | 私有；无应用发布，开发版本 0.0.0 / 0 |
| 内部在线＋本地 MVP | P0–P3，含 P2-L | 私有候选产物与设备验收，修复阻断问题 |
| 首个公开测试版 v0.1.0 | P0–P3（含 P2-L、P2-M）+ 14 性能、15 视觉、16 代码及全部首次公开门槛、证据和用户明确批准 | 发布为 prerelease；公开操作另需用户批准 |
| 日常使用正式版 v1.0.0 | P0–P5（含 P2-L）+ 相应验收与发布门槛 | 在用户本地库之外增加在线持久下载、下载库、扩展长时/恢复测试及完整发布材料 |

首个公开测试版允许暂不具备 P4 在线持久下载，但**本地播放器是必需能力**：无在线账号、无任何网络仍能浏览已授权文件、管理本地收藏/播放列表并播放。P2-L 在共享 P1 后，与在线 P2 可并行；DEV-206 及 DEV-211–216 功能就绪即可进入 P3 集成，DEV-217/218 随 DEV-301–304 收敛，最终 DEV-305 等待本地与在线验收全部通过；具体见 [17 本地计划](17-本地音乐功能与实施计划.md)。登录失败不阻止已验证的本地独立工作，但首版不能静默改成仅本地发布。README 和 Release 必须区分用户本地曲库、导入副本、下载库与临时缓存，不能描述为完整 1.0。即使把首次公开推迟到 P5，默认首个公开版本仍为 0.1.0 prerelease；调整产品与版本计划需另获用户确认。

按 [05 任务与估算](05-开发阶段与任务清单.md)，本地增加8–12人日，用户自填 Meting 初始兼容服务增加2–4人日，首版合计 **32–46人日**、1.0合计 **45–64人日**。已包括对应设置/UI/性能与测试，不重复计入P0/P3，也不含服务部署或未知封装适配。当前仅文档调整，不代表已开工。

当前 **0.0.0 / 0** 仅为初始占位，没有永久固定值或字节校验要求。contribution/main 拒绝非 OnlineMo 作者的版本文件变更；OnlineMo 的版本 PR 自动校验精确 `x.y.z`（无 `v`、后缀、前导零）与不超过项目采用的 Google Play 兼容上限 2100000000 的整数 versionCode，两者都必须严格高于 base 和全部发布 tag。普通 Debug 使用 `.dev` 与独立稳定 Debug 证书，依靠 source SHA、build SHA 和 Actions run 识别产物；PR 使用临时证书且无 secrets。

发布在临时 runner 中从已审阅 main SHA 创建 detached 快照，仅改版本文件并打 tag，**不创建额外发布分支**。所有者网页输入的 versionName 须高于全部精确发布 tag 且不低于 main 候选 versionName。最终 versionCode 为 `max(main 完整可达提交数 + 1, 既有发布 tag 最大 code + 1)`，无 tag 时最大 code 为 0；加 1 计入本次发布版本提交。必须 `fetch-depth: 0`，浅克隆失败，统计精确 main 源 SHA 的全部可达历史，不使用 `--first-parent`。main 手填 code 不参与最终发布计算；所有者版本 PR 仍保留格式及 base/tag 递增检查，最终 code 遵守上述 Google Play 兼容上限。仅用所有者手动触发运行的短期 `GITHUB_TOKEN` 推送新 tag、发布 Release，不回写 main/contribution、不合回快照、不使用 deploy keys。完整约定见 [仓库治理与发布](10-仓库治理与发布.md)。

## 2. 首次公开与发布门槛

首个公开应用版本必须满足以下全部门槛；当前没有应用、APK 或实机证据，不能提前标为通过。

- [ ] P0：实际 Watch X2 型号/API/ABI、安装、网络、扫码和熄屏播放验证完成；DEV-005 证明实际 MediaStore/文件选择器/SAF 中至少一条合法持久访问路径，候选容器＋编码有实测结论；无路径保持阻断。
- [ ] P1：精简工程、媒体服务、焦点、耳机断开及队列恢复完成。
- [ ] [18 通用接口](18-通用音源接口预留.md)：网易云/本地当前所需的来源身份、账号范围与共享资源解析解耦；同 ID 不同源、未知源、账号切换、旧响应、分页与缓存隔离有证据；未预定未来平台或构造无使用者的模块。
- [ ] P2：真实登录、喜欢/歌单/日推、歌曲搜索分页和在线播放闭环完成。
- [ ] P2-L：DEV-211–218 全部通过；本地扫描/增量 Room、分类/搜索/排序、播放列表 CRUD/重排和收藏、URI 共享播放、按需封面/LRC、缺失/撤权/重授恢复完成；没有全库 JSON、无界扫描或失败清库。
- [ ] P3：圆屏三页、逐行歌词、返回/表冠降级、错误反馈完成；未登录/账号过期/完全断网仍可从菜单进入本地库，列表编辑与来源/索引移除不删除外部原文件。
- [ ] P2-M：DEV-221–224、FR-17、T-32–35 通过；用户可填/自建 Meting 地址、测试与启停，无公共默认服务、正常/本地无额外请求、有限取消和凭据隔离；受控协议及媒体证据明确，不宣称全部歌曲解锁。
- [ ] [14 性能预算](14-性能优先与资源预算.md)：首版适用预算、至少 1000 首本地库的首扫/增量扫并行播放、内存/响应/耗电及失败取消回归有同条件证据；未测不算通过。
- [ ] [15 界面设计与视觉验收](15-界面设计与视觉验收.md)：在线和本地页面、圆屏/字体矩阵、扫描/授权/错误、列表 CRUD/重排及导入副本删除确认逐项通过；不存在外部原文件物理删除入口。
- [ ] [16 代码规范与可读性](16-代码规范与可读性.md)：数据/播放器/权限职责、取消/错误、命名与资源生命周期经审查；实现与来源记录一致。
- [ ] 云端对待发布的精确快照完成单测、lint、Release 编译，读取 APK 实际 versionName/versionCode、正式包名并校验签名指纹和 SHA-256；在 `build-manifest.json` 保留 source/build SHA、main 完整可达提交数及含本次发布提交的计数，并保留 run 和产物证据。
- [ ] Watch X2 使用该云端产物完成安装、扫码、播放、切歌、耳机断开和至少 60 分钟在线熄屏测试，并提交脱敏报告。
- [ ] 同一待发布产物完成无账号、无任何网络请求的本地启动/浏览/搜索/列表管理/播放，以及至少 **120 分钟本地熄屏**测试；完成 [06](06-测试验收与风险.md) 的 T-23–31 与 17 的撤权/重授、缺失/移位、清缓存/退出不误删曲库等场景。原文件缺失由一次性样本/文件管理器模拟，不靠产品删除 UI；P4 下载测试不能替代此门槛。
- [ ] 无已知阻断崩溃、凭证泄漏或意外外放；未完成能力和设备限制写明。
- [ ] 复用代码有固定 SHA、来源与许可记录；所分发字体/图标/其他资源有清晰来源。
- [ ] 本项目全部历史、文件、Issue/PR 材料和产物检查无真实邮箱、凭据、签名私钥、私有恢复仓库标识及 AI 协作者署名。独立私有恢复仓库不在公开范围内。
- [ ] main/contribution 保护实际生效：必须 PR，`cloud-gate`/`pr-policy` 绑定预期 GitHub App，strict 要求最新状态，禁止强推/删除，管理员受约束且无绕过；批准审阅数为 0，所有者人工审阅并独自合并。
- [ ] tag 更新/删除被禁止，创建限写入者；只有 OnlineMo 与其手动触发发布的临时 token 有所需内容写权限，不授予公开贡献者写权限。所有者专属发布及仅新增快照 tag 的行为经验证。
- [ ] 可信 `pull_request_target` 检查仅用固定 base SHA 的策略与只读 API，拒绝非 OnlineMo 作者的版本文件变更，对 OnlineMo 的版本 PR 自动校验格式及相对 base/全部发布 tag 的双项递增；Actions 路径仍拒绝所有 PR（包括所有者）的新增、修改、删除和重命名，不执行 PR 代码。Actions Issue 与所有者直接认证维护、必要时恢复保护并留档的方式明确。
- [ ] 安装、云端构建、反馈指南、首版说明、仓库级签名 secrets 与恢复验证完成；证书和 APK 指纹与 [.ci/signing-certificates.json](../.ci/signing-certificates.json) 一致。
- [ ] OnlineMo 审阅所有证据，明确批准公开仓库和发布 0.1.0 prerelease。

`.ci/release-readiness.json` 必须对应真实验收记录，不能为了让工作流通过而提前勾选；只有所有者根据证据更新。设备报告路径须指向已提交的 docs 文件。发布当次重新运行构建检查，不用过往 run 替代；重建产物若与已测 APK 的校验值不一致，必须重新完成对应产物的验收，不把旧设备报告直接套用。

### 现有 readiness 字段的复合门槛

本轮不修改 readiness JSON、脚本或 Actions。现有发布脚本对字段集合做精确匹配，门槛键仍固定为 `P0_device_and_login`、`P1_playback_foundation`、`P2_online_features`、`P3_round_watch_mvp`、`watch_x2_background_audio`、`privacy_and_source_licenses`、`install_and_known_limitations_docs`、`branch_and_tag_protections`、`signing_backup_verified`；顶层 `device_report`、`owner_approved` 也不变。不新增 `P2_local_features` 等键来造成脚本失配，也不将任何值提前改为 true。

在所有者通过 Actions 流程变更 Issue 协调将来的字段/脚本调整之前，下列现有键按复合门槛人工审阅：

| 现有键 | 设置 true 之前必须具备的证据 |
| --- | --- |
| `P0_device_and_login` | 原设备/登录证据 + DEV-005 本地来源、权限与实际容器/编码探针 |

其余键保留原有全部要求。上述映射是所有者查验证据的文档契约，**不是脚本已经自动核验本地测试、性能、视觉或可读性的声明**；文档存在也不等于证据。后续若拆分机器字段须同时协调相关校验与受保护 Actions 维护，本次不创建 Issue 或改变发布政策。

签名证书已独立生成：Release/Debug 均为 RSA 3072、SHA-256、30 年有效期；CN 分别为 `OnlineMo MeloX Watch Release` / `OnlineMo MeloX Watch Debug`，O 为 `OnlineMo`，OU 为 `MeloX Watch`，没有 C/ST/L/email。生成证书与固定指纹不等于云端配置完成。当前私有套餐的 environments 可能不支持，采用仓库级 Actions secrets，配置和验证状态仍以 13 文档为准。

用户已明确授权将 p12、明文密码及恢复元数据保存于**独立且永久私有的恢复仓库**。恢复仓库必须关闭 Actions、没有协作者；本项目公开时仍不得公开它。公开材料只描述通用恢复方式，不记录密码、仓库名称或地址。

## 4. 公开操作顺序

先在私有阶段完成 P0–P3（含 P2-L）、14/15/16 全部门槛、候选云端产物与在线/本地设备验收，整理精确提交、校验值和首版说明；审查整个已有历史。候选构建按发布快照规则验证，不提前推送正式 tag；若源码、版本分配或产物变化，需重新核验对应证据。

公开前解决规则可用性。升级 GitHub Pro 可在私有阶段启用并验证保护；若选择通过公开解决套餐限制，须在其他门槛和证据完成后，由用户明确批准可见性变更。**公开后立即执行 GOV-PUBLIC-01：按 [10 文档第 6 节](10-仓库治理与发布.md) 配置并核验 main/contribution 和发布 tag 保护，完成后才继续发版。** 用户已要求这一步，不等再次提醒或重复授权同一配置；公开本身和实际发版仍各自需要明确批准。保护未验证前不发布、不开放贡献者写权限。自动工作流不自行改变可见性。

- [ ] 已公开的应用仓库完成 main、contribution 两条精确保护规则：必需 PR、`pr-policy`/`cloud-gate` 绑定 GitHub Actions、strict、会话解决、管理员同样受限、禁止强推/删除；单人批准数为 0，无永久绕过。
- [ ] 已启用并核验 v* 禁改删规则，保留所有者授权创建新 tag 的能力；恢复仓库仍私有。
- [ ] 已读回真实配置并记录正常 PR 与检查证据，更新 13 文档；只有此时才可将 `branch_and_tag_protections` 标为通过。

这份清单只记录未来必须执行的步骤，当前全部未勾选。配置失败时停在“公开后保护待完成”，不进入 Owner release，不把其他绿色 CI 当作保护已经生效。

完成全部门槛和明确授权后，仅由 OnlineMo 在网页 **Actions → Owner release → Run workflow** 选择 main 手动触发，无需本地电脑；核验 detached 快照及对应产物，只创建新的 v0.1.0 tag 和 prerelease。若 tag 已创建而 Release 上传失败，恢复该 tag 对应的同一 Release，不删除、覆盖或重用版本；发布不回写开发分支。网页发布可行性的讨论不构成发布授权，本次未执行发布。

即使未来规则生效，所有者仍可重新配置；CI 不能单独阻止管理员直接推送。当前 403 与保护缺失必须如实保留在状态记录中，不能把本清单当作已通过的验收报告。
