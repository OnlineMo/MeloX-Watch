# 本地播放器全量需求整合

本文件依据用户提供的匿名功能报告，**F-001～F-128全部纳入MeloX-Watch必须实现范围**，包括原报告标记“范围待明确”的13项。原报告的参数/平台待核验事项不是删项许可。规划整合时未实现应用；用户恢复后DEV-004-A、P1、LP-01～05及LP-07～09正在建设，实际状态见13及development记录，尚无原AC通过证据。

原文按内容哈希固定在 [匿名需求基线](requirements/local-player-F001-F128.md)，不修改外部源文件。原稿115已确认/13待定是历史状态，当前以本文件的128必做决定为准。正常与异常共256个原始AC编号保留；“候选契约”“纳入后”等旧措辞现在都按必做契约解释，参数另行落实。

功能矩阵的机器记录为 [local-player-coverage.json](requirements/local-player-coverage.json)，源摘要为 [local-player-source.json](requirements/local-player-source.json)。报告是匿名功能输入，不是上游代码、应用身份、产品更名或设备事实；不导入外部项目的签名/账号/仓库/原始调研材料。

## 1. 范围优先级与完成定义

- 当前用户全量要求覆盖旧计划中“首发不做/后续可选”的冲突条款：原文件删除/移动/标签写入、M3U/JSON交换、备份恢复、速度/ReplayGain/无缝/CUE/APE/DSD、双后端切换、音效、Wi-Fi传歌与手机配套、主题/字体/逐字歌词/常亮、显式联网补全均必须实现。
- “可选”只表示运行时用户可启停，例如联网补全和配套连接；不是开发范围可省略。离线核心仍不依赖账号、网络或手机常驻。
- 分组只规定依赖和交付顺序。内部可逐批构建/测试；对外称为完整本地播放器、完成首版门槛前必须128项全部有实现与AC证据。若有技术阻断，列明具体项和解决任务，不自动降级成一个较小MVP。
- 能力相关功能可按原报告在特定设备/后端诚实禁用，但项目层面不能仅做“不支持”提示就标完成：需在声明支持的后端/授权方式/兼容接收端跑通正常AC，并覆盖不支持环境的异常AC。做不到则全局验收仍未通过。
- 性能第一、视觉第二、可读性与文件安全是底线；用有界实现和用户启停控制成本，不能用性能优先把已确认功能删掉。
- 不再给出人日、日历工期、代码行数或工作量估算。仅维护范围、依赖、决策、实际状态和验收。

## 4. 待决细节的处理

范围已确定；技术参数、协议、设备能力仍需按17的决策表在其依赖实现前落实。每个未决项必须有负责LP任务、候选方案、验证材料和退出条件；不把“待明确”复制成无限期占位，不虚构已经测过的设备能力。

源报告的“前置条件”有些是来源选项或复用关系，并不都是必须同时满足：MediaStore与SAF可分别实现/验证；无选择器替代路径不能先要求选择器成功；歌词可来自同名LRC、内嵌或手动关联，不能强制先有同名LRC；标签编辑/移动依赖写权限不依赖真的删除文件。实际无环实施顺序由05定义，并完整回归原AC。
