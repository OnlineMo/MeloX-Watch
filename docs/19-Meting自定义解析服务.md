# Meting 自定义解析服务

状态：用户已要求加入开发计划，尚未实现或请求任何实际音乐服务。**服务地址由用户填写，支持自建，不内置、推荐或自动回退到公共 API。** 本文件描述本次明确要求的 Meting 兼容适配；其他未来音源仍遵循 [18 通用接口预留](18-通用音源接口预留.md)，不提前指定平台或接入方式。

Meting 接入用于尝试取得服务能够提供的网易云歌曲资源，不承诺“所有歌曲解锁”。返回空、试听、权限错误、不可访问或受保护资源时如实呈现，不能将短音频伪装为完整版。实际能力由用户配置的服务及响应决定，不以 API 名称代替验证。

## 1. 在应用中的位置

网易云仍提供既有登录、喜欢、歌单、搜索和曲目身份；Meting 是用户选择的**可选播放解析服务**。`TrackKey(providerId, trackId)` 保留歌曲原始来源，另记录 `resolverId`、服务配置版本和实际资源来源，不因更换解析服务复制一套音乐库或更换曲目 ID。

本地文件直接按本地 URI/授权处理，不访问 Meting，不被在线账号、网络或服务开关影响。播放器仍只有一个，页面不直接拼接 API 请求。当前直连解析和 Meting 适配位于同一 `PlaybackResolver` 的可替换解析步骤；未来有真实需求再新增实现，不能把此服务当作所有未来音源必须使用的协议。

## 2. 用户设置与自建服务

| 设置 | 计划行为 |
| --- | --- |
| 使用自定义解析服务 | 默认关闭；必须由用户填写有效地址并主动启用；空配置不会产生网络请求 |
| API 地址 | 支持完整 endpoint 或受限 URL 模板；保留用户自建路径和必需参数，不硬编码任何公网域名 |
| 模板模式 | 初始仅支持 `:server`、`:type`、`:id`，按 URI 规则编码；未知占位符在保存时提示，不默默替换。其他封装需要的 `:r`、`:auth` 等只有另行实现并验证后才声明支持；不执行脚本 |
| 额外鉴权 | 仅当服务需要时配置该服务自己的凭据；加密保存，不使用用户的网易云 Cookie 或服务端签名主密钥代填 |
| 测试 | 使用当前网易云曲目或用户明确填写的测试曲目 ID 请求；无曲目时提示需要 ID。分别报告地址有效、协议兼容、资源解析及实际播放结果，不能只凭 HTTP 200 宣称可播放 |
| 启用后的策略 | 正常网易云路径优先；仅在本次资源不可用/解析失败且仍有时间预算时尝试已配置服务。提供显式重试入口，不循环切源 |
| 更改/关闭/删除 | 增加配置代次并取消旧请求，废弃旧服务的短期资源缓存；不删除歌曲、队列、本地库或账号；不主动向新地址转发旧凭据 |

输入可复用已有系统输入能力；不得借此偷偷增加手机伴侣或无线传歌项目。保存 API 的界面应说明它将收到所解析的曲目 ID。URL 本身可能包含秘密参数，列表只显示脱敏的服务名称/主机；日志、截图、错误和普通设置导出不包含完整 URL、token 或查询凭据。

HTTPS 为默认。用户自建局域网可能使用 HTTP，须作为显式选择记录；按 Android 网络安全配置实现并测试，不能“关闭所有 TLS 校验”解决证书问题，也不允许 HTTPS 静默降级。HTTP 自建访问不是允许任意 `file:`、`content:`、`javascript:` 或 `intent:` URL；服务返回的远程播放资源仅按允许的 HTTP(S) 处理，本地 URI 只来自本地授权路径。

## 3. 明确支持的初始协议形态

静态审阅的常见 MetingJS/APlayer 兼容形态为：歌曲详情返回包含 `name`、`artist`、`url` 及可选 `pic`/`lrc` 的数组，`url` 也可能是带签名参数并返回 HTTP 跳转的解析端点。这只是初始兼容配置，**并非所有名为 Meting 的服务都具有同样格式**。[M1][M2]

首版以该形态定义清晰的请求/响应适配及版本记录：

1. 当前网易云曲目的请求映射为 `server=netease`、`type=song` 与该曲目 ID。endpoint 模式安全拼接参数；模板模式仅处理声明的占位符。未知来源不默认映射网易云，也不提前映射未来平台。
2. 验证状态码、响应大小上限、JSON 结构、字段类型及单曲结果。错误对象、空数组、HTML 页面或无法唯一确定曲目的多项结果均不得直接取第一项冒充成功；缺失元数据沿用原曲目快照，不能臆造质量/时长。
3. 使用响应里的音频 URL，保留服务返回的必要签名参数；不要求客户端获取自建服务的签名主密钥，也不从原曲目 ID 猜测 `url_id` 或重算签名。
4. `url` 跳转按有界链路处理，不把音频流完整读入内存，也不把 HTML/JSON 错误交给播放器当音乐。跨主机跳转不携带该 API 的 Authorization/Cookie；不向媒体 CDN 自动发送用户网易云凭证。
5. 可读媒体仍须验证实际解码、seek、首声和结束行为。服务未提供可信质量、有效期、试听范围时记录未知，不把“请求 320”当作实际 320kbps，也不自动标记完整版。
6. 不兼容的用户服务给出可理解错误及修改/关闭入口，不偷偷换成项目指定的公共服务。其他封装以后按真实样本增加小适配，不增加可执行远程脚本。

本次不将 MetingJS/APlayer、Node.js、PHP 或整套服务端搬进手表；Android 端只需要与已选择协议兼容的 HTTP 适配器。

## 4. 性能、时序与结果语义

- 不在启动、列表滚动或每个进度 tick 检查服务；只在用户测试或当前曲目确实需要解析时调用。合并同曲目、同配置、同账号代次的重复请求，不预解析全歌单。
- 正常直连成功路径不增加串行 Meting 请求。首次失败后的补充解析纳入总超时预算，按 [14](14-性能优先与资源预算.md) 测量；请求放在可取消 IO 边界，主线程不等待网络。
- 每次用户点歌最多进行一轮服务补充解析；单轮中的协议请求、跳转和实际媒体失败仍须有上限。失败后停止并提示，不与原解析器相互触发形成无限循环。后续用户主动重试才创建新一轮。
- 切歌、退出、配置更改、关闭服务后，旧回调不得抢播或污染新状态。缓存键包含原曲目身份、账号相关范围和服务配置代次；有效期未知时只在有界短期内使用，失效后重新解析。
- 显示“通过自定义解析服务播放”及实际可确认的来源/质量；服务无法保证曲目版本一致时不自行搜索同名曲替换。缺封面/歌词不延迟首声，本地歌曲不借服务联网补全。
- 用户所说的播放资源补充不自动授权下载；P4 下载仍有独立能力/权限和完整性验证，不能通过播放地址就直接开放下载按钮。

首版必须交付可配置的适配功能与其受控验证；不要求每位用户自建的未知实现都通过，也不把公共服务不可用当成本地音乐失败。有真实用户服务时可另附其验证结果；没有真实第三方服务实测时，明确仅验证初始协议和受控资源，不能宣布网易云曲库已全部“解锁”。

初始兼容形态预计额外 **2–4 人日**，含设置、解析与回归，不含部署服务或适配所有第三方变体。首版原 30–42 人日调整为 **32–46 人日**，1.0 原 43–60 调整为 **45–64 人日**；均待实际服务/设备验证后修订，不声称零成本。
