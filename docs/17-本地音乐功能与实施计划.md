# 本地音乐功能与实施计划

状态：用户已确认把本地播放器加入项目；**本文件仅落实文档范围与实施计划**。Android 工程尚未实施，生产/测试代码、APK、设备与性能结果均不存在。所有任务和验收保持未完成，不因上游已有代码或本文件建立而算作通过。

本地能力是首个公开 `0.1.0` prerelease 的必需部分：P0 探针、P1 共享基础、P2 在线与 P2-L 本地功能、P3 集成均需完成。`1.0.0` 在此基础上完成 P4 在线下载和 P5 收敛。发布版本、所有者职责和授权方式继续遵循 [12 首个公开版本与责任清单](12-首个公开版本与责任清单.md)。

## 1. 用户场景与首发范围

打开应用即可选择“本地音乐”或“在线音乐”。本地入口、来源授权、扫描、浏览、搜索、收藏、播放列表和播放都不要求在线账号或任何网络请求；账号过期提示不能遮挡本地入口。没有音乐时引导添加实际可用来源，不跳转扫码。在线“我喜欢”和歌单仍只读，本地收藏与播放列表可编辑，名称和数据分开。

| 场景 | 首版必需行为 |
| --- | --- |
| 手表已有音频 | 通过可用的 MediaStore 或系统文件/目录选择器引用授权 URI，扫描后即可播放 |
| 分类选歌 | 歌曲、专辑、艺人、文件夹、本地收藏、本地播放列表；未知标签有稳定回退，文件名仍可辨认 |
| 搜索与排序 | 在本地索引检索曲名、艺人、专辑、文件名；按适用字段及方向稳定排序，分页结果不重复/漏项 |
| 播放列表管理 | 新建、查看、重命名、删除，增删成员及持久重排；取消/失败保留原状态，删除列表不删音频 |
| 本地收藏 | 收藏/取消收藏及独立列表，重启仍在，退出或更换在线账号不清空 |
| 播放与歌词 | 与在线共用单个播放器/会话/队列/焦点/耳机控制；按需本地封面和 LRC，无图/无歌词不妨碍播放 |
| 文件或权限异常 | 显示缺失、移位、访问失效等原因，保留索引和用户整理结果，提供实际可用的重授/重扫/重新定位入口 |
| 完全离线外出 | 没有账号、关闭所有网络仍可冷启动、选歌、管理列表和连续熄屏播放至少 120 分钟 |

首发不内置 Wi-Fi 传歌、手机伴侣导入服务、标签编辑、CUE、额外解码器、DRM 解密、在线识曲或联网补全本地封面/歌词。音频进入手表依赖用户已有文件和 P0 实测可用方式，不能虚构传输入口。

**首发不提供外部原文件物理删除 UI。** 移除来源或索引保留原文件；应用持有的显式导入副本可单独确认删除。缺失/移动测试使用一次性样本，由系统文件管理器等方式操作，不为测试增加产品删除能力。界面细节以 [15 界面设计与视觉验收](15-界面设计与视觉验收.md) 为准。

## 2. P0 文件访问、权限与格式探针

DEV-005 的操作记录在 [07 首阶段设备核验](07-首阶段设备核验.md)。先核验真实固件，再决定入口，不从“普通 Android”推断手表必有文件选择器、DocumentsUI 或可用的 SAF provider。

| 路径 | 计划契约 | 必需验证 |
| --- | --- | --- |
| MediaStore | 查询设备音频集合，通过 `content://` URI 读取；按实际 API/target 申请音频读取权限 | 已知文件可被发现并打开；空集合、拒绝与错误分开；只扫描授权范围 |
| SAF 文件选择 | 仅在支持时使用 `ACTION_OPEN_DOCUMENT`，保存返回的合法 URI | 触控可完成选择、取消正确；是否允许持久读取须核验返回的授权标志 |
| SAF 目录选择 | 仅在支持时使用 `ACTION_OPEN_DOCUMENT_TREE`，扫描所选树 | 树范围、子目录枚举、重启与撤权恢复；不越过 provider/系统限制 |
| 必要的显式导入 | 已合法打开源文件，但不能可靠持久引用等场景下，由用户选择复制到应用空间 | 先说明副本/容量，检查配额与保留空间；源不可读时复制不能成为绕过权限的手段 |

MediaStore 读取其他应用的音频按系统版本核验 `READ_MEDIA_AUDIO` 或适用旧版读取权限；SAF 依赖用户授予的 URI 权限，只有实际允许持久化时才保存持久授权。拒绝/撤销对应稳定错误和恢复入口，不循环弹框，不把失败当成成功空库。禁止 `MANAGE_EXTERNAL_STORAGE`、root、猜测私有绝对路径或绕过固件限制。[O1][O2]

至少一条面向用户、能持续访问设备音频的合法路径必须有证据；不要求所有设备同时支持全部入口。临时样例内置音频、模拟器或仅能依赖网络的云文档 provider 不能代替这一门槛。没有支持路径则阻断本地阶段；独立登录失败则阻断在线阶段，已验证的另一条业务路径仍可推进独立工作。两条产品路径的门槛都满足之前，不得把首版静默改为仅在线或仅本地发布。

以下只是候选样本，平台/Media3 对容器的支持不等于目标固件具备全部音频解码能力。[O3][O4] 按容器、实际编码、编码参数和设备逐一建立矩阵，不能按扩展名宣称全格式支持。

| 候选文件 | 至少区分的实际组合 | 验证与范围说明 |
| --- | --- | --- |
| MP3 | MPEG 音频/MP3，固定与可变码率样本 | 首声、时长、seek、自然结束、坏帧 |
| AAC / M4A | ADTS 中 AAC；MP4/M4A 中 AAC，标明 profile | M4A 是容器用法，不能由后缀推定 AAC profile 或其他编码均可用 |
| FLAC | 原生 FLAC，记录位深/采样率/声道 | 资源消耗和解码成功均实测，不宣称所有高规格可用 |
| WAV | RIFF/WAVE 中 PCM，记录位深/采样率/声道 | WAV 可封装其他编码，不能泛化已测 PCM 结果 |
| Ogg / Opus | Ogg 中 Vorbis、Ogg 中 Opus 分开 | 记录实际容器/编码；不把任意 Opus 容器都列为已支持 |

记录样本来源/摘要、实际格式参数、固件/API、构建与结果；不支持和损坏分别给 `UnsupportedFormat` 或适当读取错误，不自动联网找替代曲，也不引入额外解码器或 DRM 解密来凑支持清单。

## 3. 存储所有权与清理

P2-L 是用户文件曲库，P4 是在线资源持久下载；“本地可播放”不表示两者权限和生命周期相同。

| 资源 | 存储与身份 | 清理、退出和删除边界 |
| --- | --- | --- |
| 用户外部文件 | 设备范围的逻辑曲目 ID、MediaStore/SAF URI 与授权引用，默认不复制音频 | 清缓存、退出/切账号、移除来源/索引、删除列表均不删原文件；首发无原文件物理删除 UI |
| 显式导入副本 | 应用持有的持久音频、独立来源类型/配额与原始来源记录 | 清缓存/退出保留；只有“删除导入副本”的明确确认才删除该副本，原文件保留 |
| P4 持久下载 | 在线 provider/账号/曲目/音质/下载权限及完成索引 | 使用独立下载管理；不伪装成用户本地文件以绕过权限，切账号不继承资源访问状态 |
| 流媒体缓存 | 有容量与淘汰策略的临时在线字节 | 可清理，不能当完整下载或用户音频；本地 URI 直接读不走 HTTP 缓存 |
| 本地封面/LRC 派生缓存 | 可重建的缩略图/解析结果，独立容量上限 | 可清理派生数据，不删除外部图片/LRC、音频、本地索引、收藏和列表 |

来源移除只停止访问/扫描该来源；应用不再需要的该来源授权可按用户操作释放，不能由在线退出顺带撤销。存在其他仍有效访问别名的曲目继续可用；仅剩被移除来源的记录标为用户移除/不可用。索引移除保留历史/列表所需的轻量身份或占位引用，不级联误删用户整理结果；再次扫描可能重新发现原文件，要在界面说明。

显式导入在临时副本完成写入、校验和受控提交之后才登记为可播资源。大小未知时仍需按实际写入量检查配额和剩余空间；低空间/取消/失败关闭流并清理未完成的应用临时副本，保留已完成副本与外部原件。配额与保留空间遵循 [02 产品默认值](02-产品需求与范围.md) 和 [14 资源约束](14-性能优先与资源预算.md)，未设定独立上限不得开放复制。不自动复制整库，不自动把网络资源下载当成本地导入。

删除导入副本确认说明范围、名称和数量；若当前正在播放该副本，明确停止该曲的影响，确认后同步服务状态、索引与文件结果。失败不报告已删除，部分成功逐项记录；取消不改变文件或列表。

## 4. 数据模型与 URI 身份

本地曲库是设备范围，与在线账号分开；收藏、列表和历史引用稳定的 `TrackKey(local, localTrackId)`。具体类型命名服从 [03 架构契约](03-技术架构与接口.md) 与 [16 代码规范](16-代码规范与可读性.md)，下表为未来设计，不是已有实现。

| 记录 | 必需字段或职责 |
| --- | --- |
| `LocalTrack` | 稳定逻辑 ID、标题/文件名/艺人/专辑/时长、实际格式信息、可用状态、加入时间；不以在线歌曲 ID 定义本地身份 |
| `LocalSource` / `LocalUriAlias` | 来源类型/范围、URI、provider/卷或文档身份、授权状态、可用性、大小/修改时间等变化指纹、lastSeenGeneration；导入副本标明所有权 |
| `LocalScanRun` | 来源及范围、generation、状态、实际计数、完整枚举标志、错误/取消原因、开始/结束记录 |
| `LocalPlaylist` / `LocalPlaylistEntry` | 列表 ID/名称，成员逻辑 ID 与持久顺序；事务保存，缺失成员保留占位 |
| 本地收藏与历史 | 逻辑 ID、收藏状态/顺序（如适用）、播放历史；不依赖在线 accountId |
| 封面/LRC 引用 | 已授权来源或派生缓存 key、来源变化指纹/解析版本、状态；不把全库图片或歌词塞进曲目行 |

优先按来源内稳定文档/媒体身份及可靠 URI 映射建立唯一约束。URI 规范化不能改写 provider 的文档 ID 或假定 `content://` 等于磁盘路径。MediaStore 与 SAF 可能指向同一文件：有可信身份映射才共用逻辑 ID/别名；无法证明时保留各自来源，不能按相同标题、艺人、时长或文件名自动合并，也不为去重读完整个库的音频内容。

移动/重命名后 URI 可能失效或变化。若来源能证明是同一文档，更新访问别名；否则保留旧曲目缺失状态，通过可靠内容证据或用户明确重新定位确认后关联回原逻辑 ID。确认前不自动把同名新文件继承为旧曲；确认后事务更新别名并保留收藏、列表顺序和历史，不生成第二份播放历史。

## 5. 扫描、增量更新与失败一致性

使用 Room 分批事务保存索引、列表和扫描状态。分类、查询、排序在数据库端分页执行，不能先取全库再切页；不使用 SharedPreferences 整库 JSON 反复读写。缺标签回退文件名/未知艺人/未知专辑，分组不能改变文件身份。相同排序键用稳定 ID 等补充顺序，返回保留位置；扫描更新不无提示地重置用户正在编辑的列表。

扫描/元数据读取采用**全局有界工作队列、初始并发 1**，批大小等起始调度值统一见 14。限制待处理队列、每批数量和每个资源的读取量；不为每个目录/文件递归创建 async 后再用局部 Semaphore 冒充全局限流。IO、元数据与数据库查询不在主线程，数据库事务不包住目录遍历。播放优先，扫描和封面提取争抢资源时降速或在批边界暂停。

1. 用户选择/刷新来源后创建绑定范围的 generation；合并相同范围的重复扫描请求，旧任务不能覆盖新代次。首扫和重扫都保留已有库可读。
2. 枚举一批 URI 与轻量字段，按可靠变化指纹更新已变更文件；无可信修改信息时仅对候选文件做有界复核，不把未知视为未变化。观察到的变更只作提示，仍需要用户可见的刷新路径。
3. 每批事务 upsert 已确认记录及别名的 `lastSeenGeneration`，单文件读取失败保留旧信息并标错误；不等待整库完成才显示首批，也不读取全库封面/LRC。
4. 只有该来源/范围**完整枚举成功、授权仍有效且 generation 仍为当前任务**，才能完成扫描并对账；未见别名标记缺失，所有有效别名都不可用时才将曲目标缺失。不自动物理删文件或级联删列表、收藏、历史。
5. 取消、异常、进程中止、撤权、provider 不可用、深度/数量/时间边界导致的部分遍历都记为未完成/部分完成；保留旧索引与已确认批次，**不得删除或判定未见曲目已经消失**。按失败来源重试，不能用成功子目录的结果清理失败范围。

全量扫描的 generation 对账按来源范围进行，增量变更通知本身不能当作完整枚举。已见但元数据失败的文件和完全未见的文件分开；源文件成功打开后才更新可用状态。事务失败不损坏上一个已提交批次，取消需继续传播并释放 Cursor、流与元数据读取器。

初始生命周期策略：任务由本地仓库协调，页面间导航不创建重复扫描；应用整体退后台/熄屏时在安全批边界暂停非关键扫描并记录部分完成，音频服务继续。进程结束后不保留假“运行中”，再次进入显示需要刷新；首版不承诺跨进程游标续扫，用户重扫创建新代次。不得为扫描常驻唤醒或周期全库轮询；若未来要改变后台任务策略，另行核验平台能力和 14 预算。UI 隐藏时停止进度刷新，不把 UI 停止刷新宣称为任务完成。

## 6. 本地库、列表与共同播放

本地菜单提供独立分类页，不把所有功能塞在播放页。搜索取消旧查询并区分索引为空/尚未扫描/只完成部分/权限失效；排序字段及方向可记忆，视图排序不静默改动当前队列。列表名称为空不提交，同名不覆盖已有列表；修改成员、收藏与顺序使用 Room 事务，失败保留编辑草稿及原状态。

顺序编辑是必需能力，按 15 提供上移/下移/移至位置和保存/取消，不依赖拖拽或表冠。列表删除只删除列表与成员关系，取消收藏只改收藏关系；都不删除曲库或音频。根据列表发起播放时使用当时的顺序，之后改列表不静默替换活动队列。

`PlaybackResolver` 按来源分派：本地用逻辑 ID 找到有效 URI/导入副本、检查访问并交给共享 Media3；在线才执行账号/URL/下载权限逻辑。本地缺失或撤权不回退在线搜索、在线音质或同名歌曲。所有页面仍连接单个 `MediaSessionService` 和单个 ExoPlayer，复用队列、播放模式、焦点、媒体键、耳机断开暂停、默认暂停恢复与歌词时间线。

切在线账号只影响相应在线条目和任务，不能停止不需要账号的当前本地音频或清空本地历史；混合队列中的在线条目标记所需账号状态，保留本地条目。无可播项时停止并解释，失败跳过/重试有上限，不无限循环。

本地模式不启动二维码轮询、账号校验、在线目录预热、遥测、HTTP/DNS 请求、在线封面或歌词获取；本地索引与播放链路不得隐式调用在线客户端。来自云端文档 provider、需要联网才能取到的资源不算本计划的设备本地文件，P0 必须核验所选来源实际离线可读。无网络时“请求失败后还能播”也不满足“无任何网络请求”的验收。

## 7. 按需封面、LRC 与恢复

封面只为当前曲目/可见项请求，按显示尺寸降采样，限制原始读取量、像素与缓存容量；优先播放而非补图，不批量提取全库内嵌图片。损坏、过大、缺失、读取超时或撤权用固定占位，不能保留上一首封面，也不联网补图。缓存失效绑定来源指纹，清缓存后按需重建。

首版 LRC 按授权目录内同名音频关联，或让用户明确选择可访问的 LRC；仅取得单个音频 URI 不意味着能枚举同目录歌词。出现多个候选不任意串配，未找到/未授权时显示暂无本地歌词。按需读取并限制文件大小/行数/解析工作量，处理编码与时间戳异常；切歌后旧解析结果不能覆盖当前曲目。复用共享逐行时间线，不迁入识曲和网络歌词回退；不扩展标签/CUE/其他歌词编辑功能。

| 状态 | 稳定结果 | 恢复动作与数据保留 |
| --- | --- | --- |
| 初次拒绝/选择取消 | `PermissionDenied` / 取消，不能显示成功空扫描 | 保留旧库，可返回；只在用户再次操作时请求授权 |
| 已有权限被撤销 | `PermissionRevoked`，标明来源；扫描中止并保留已提交批次 | 重授同一来源后复核 URI 并增量更新，收藏/列表/历史保留 |
| 文件缺失或 URI 移位 | `FileMissing`，保留曲名、逻辑身份与原因 | 用户可重扫/重新定位；按第 4 节证据关联，不用同名匹配替换 |
| 来源暂不可用 | `SourceUnavailable`，不当作文件全被删除 | 有界重试或用户稍后刷新；其他来源可继续 |
| 坏元数据/封面/LRC | `MetadataUnreadable` 或相应附属资源错误；能播音频继续 | 文件名/占位/无歌词回退，不让附属资源失败清空曲目 |
| 不支持音频/坏文件 | `UnsupportedFormat` 或实际读取错误 | 告知未支持的组合，不崩溃、不循环重试、不偷偷找在线替代 |
| 空间不足/副本复制中断 | `StorageFull` / 取消 / 部分完成 | 保留完整副本和原件，清理应用未完成临时文件，不登记假完成 |

日志仅保留脱敏来源/错误标识，不公开用户完整目录/URI、文件私密信息或在线凭据。重授成功不能仅靠“授权窗口返回成功”判断，必须重新验证相关 URI 可打开。
