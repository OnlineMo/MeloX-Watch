## 5. 决策记录

| 编号 | 决策 | 理由 | 重新评估条件 |
| --- | --- | --- | --- |
| ADR-01 | Watch X2 普通 Android 为主，Wear OS 后续 | 用户明确指定；主流程不依赖 GMS | 实机系统与用户预期不同或用户改变目标 |
| ADR-02 | 独立轻量工程，逐项提取 Android 核心 | 上游服务/账户/下载存在 UI 和平台耦合 | 上游提供经过验证的独立核心模块 |
| ADR-03 | 首发网易云在线＋用户本地文件，共享独立播放器 | 用户新增完整本地音乐需求；在线仅一个服务来源 | 增加其他在线音源或改变本地访问范围 |
| ADR-04 | 普通 Compose 圆屏主界面 + Media3 | 无 Wear OS/GMS 硬前置，已有 Kotlin 复用路径 | P0 性能或系统兼容存在阻断 |
| ADR-05 | 在线＋本地 MVP 先于在线歌曲持久下载 | 首版 P2-L 完成本地文件库；P4 下载任务与用户本地文件分开 | 用户另行调整公开范围；不得把本地库推迟到 P4 |
| ADR-06 | QR 原生方案先验证，WebView 作为条件替代 | 两个上游实际实现不同，不能直接认定可用 | 目标环境登录失败或服务策略变化 |
| ADR-07 | 播放缓存与持久下载分开 | 上游 Watch 临时音频不构成完整离线库；下载需明确状态 | 新资源格式/下载引擎要求变更 |
| ADR-08 | LAN 控制与账号同步分开 | LAN v1 的身份/传输能力不适合直接传凭证 | 手机端完成认证加密通道和配套协议 |
| ADR-09 | 默认静态封面、逐行歌词、单播放器 | 圆屏可读性、包体与功耗优先 | 实测有预算且用户需要高级效果 |
| ADR-10 | 应用功能仍止于规划；新增仓库基础设施按后续授权实施 | 用户后续要求分支、云端构建和所有者发版 | 用户明确要求开始应用开发 |
| ADR-11 | 固定上游 SHA，升级单独迁移 | 避免新旧上游行为混用 | 完成独立升级 Issue、影响分析和回归 |
| ADR-12 | 云端编译、本地编写和设备验证 | 用户指定统一环境 | 由所有者明确变更政策 |
| ADR-13 | 性能第一、界面美观第二、可读性必须达标 | 用户明确优先级；14 统一性能预算，15 视觉验收，16 编码/注释规范 | 按实机证据调整预算；不牺牲正确性、隐私、可访问性 |
| ADR-14 | 本地索引分批增量维护，在线/本地共享一个播放器 | 固定上游有扫描/模型/本地播放语义，但整库 JSON 与批量封面不适合直接移植 | DEV-005 证实访问边界或 P2-L 性能测量需要调整；上游 SHA 不浮动 |
| ADR-15 | 按当前网易云/本地需求预留平台中立的小接口 | 用户明确不预定后续平台和接入边界；隔离身份/账号/协议，保持扩展余地 | 实际新增来源时再确定能力、流程与接口演进；不预建框架或平台模块 |
| ADR-16 | Meting 由用户自填/自建、默认关闭、作为可选解析服务 | 用户明确要求；没有内置公共地址，不混淆原曲目与服务身份 | 新封装按真实协议独立验证；不保证全曲库解锁，不替代下载权限 |

## 6. 尚未确认的项目

- 设备：SKU、API、ABI、dp/inset、安装入口、输入法、WebView、表冠事件、低电模式行为。
- 音乐服务：在用户网络和账号下的 QR/播放/下载可用性；歌曲权限；实际分页和 URL 有效期。
- 构建：新工程工具链和依赖组合；独立包名；最终签名与发布渠道。
- 手机协同：用户手机平台、是否需要 MeloX 手机端改造、LAN 可达性；首发不依赖这些答案。
- 性能：首声、内存、温度、耗电和包体预算均待测试。
- 本地文件：实际 MediaStore/系统文件选择器/SAF、持久 URI 授权、候选容器与编码支持及文件移动恢复均待 DEV-005 实测。
