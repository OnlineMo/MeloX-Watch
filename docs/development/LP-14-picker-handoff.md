# LP-14 手机伴侣的系统选择器交接

根据 F-067 的文件与目标确认、F-097 的主题素材草稿，以及 17 文档 LP-14 的取消和物理退出契约，系统文件选择结果由同一 ViewModel 中的单个内存 ticket 接收。选择器暂时停止 Activity 时，原网络和文档任务仍按既有路径关闭；返回的 URI 等待实际关闭完成，并且仅在原页面、目标和主题草稿代次仍有效且页面回到前台后，进入原有私有副本或图标准备路径。

原接线在 OpenDocument 返回时直接尝试业务准入；异步关闭尚未完成会得到 BUSY 且丢失这次合法选择。图标角色和许可原本存于 Activity 字段，配置重建后不能正确交接。现在两种选择共用一个有界内存槽，配置重建复用 ViewModel，角色和许可随原 ticket 保留；明确停止、撤配对、换页面或修改目标使旧选择失效。未返回的旧 ticket 仍占有结果槽，直到它自己的返回被消费，防止迟到结果归入后来的选择。

返回只准备本地草稿，不恢复连接、不发送文件、不应用手表主题。未配对时仍可离线准备素材；发送继续由原目标、授权、revision 和 operationId 契约裁决。URI、ticket 和待接收结果不进入 Bundle、持久记录、诊断或导出；进程结束不重放选择。ViewModel 清理丢弃未完成选择，关闭控制任务完成后结束其 scope；未退出的物理句柄继续由既有传输或文档 owner 保留并要求明确恢复。权限、无选择器、取消及恢复失败保留可解释状态和原文件。

选择器返回后，连接处于 OFF 但实际内存配对仍保留目标、设备会话和手机证书指纹时，连接页提供原有的明确认证入口。重新填写连接地址并点击后，仍由原客户端验证 TLS 指纹、会话期限、手表批准和能力集合；只保存过一个目标或未配对的状态不会因此获得入口，恢复状态仍禁止业务准入。该条件修正不自动重连，不保存地址，也不发送准备好的文件。

新增 `CompanionPickerHandoffTest` 使用既有 SDK26/Robolectric、真实 CompanionDocuments 与本地文件，受控 wire 关闭 gate 不打开 socket。14 条定义覆盖快速返回、后台等待、明确取消、迟到/重复返回、目标输入与撤配对、ViewModel 保留的图标角色/许可、启动失败、无效 URI、撤权、明确恢复、真实文档 worker 延迟退出及销毁清理。VM scope 在 onCleared 前关闭时，实际停止和文档退出之后也不能消费旧 URI；正常清理随后丢弃该内存槽。消费选择槽先于注册可能同步执行的完成回调，避免已取消的 lazy Job 重取旧选择。没有新增依赖、锁或 schema，也未修改传输协议。

上述回归定义尚未运行，源码不计作云端或设备通过。AC-067-N/E 与 AC-097-N/E 仍未验收；后继需要完整云端双端 Debug 和精确双 APK 的实际选择、传歌及主题确认。配置重建的 ViewModel 保留测试不替代真实 Activity/选择器的设备交互，原 128 项和 256 项验收范围保持。
