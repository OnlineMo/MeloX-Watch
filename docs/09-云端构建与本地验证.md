# 云端构建与本地验证

更新日期：2026-11-10。构建基线已选定，真实设备参数仍待 P0 验证。当前应用仍处于规划阶段，没有 Android 工程、APK 或设备测试结果。本文是接入与运行要求，不代表云端设置或发布实现已全部完成；实际启用情况见 [仓库状态](13-仓库状态.md)。

## 1. 固定基线

唯一配置为 `.ci/toolchain.properties`：Ubuntu 24.04、Temurin 17.0.17+10、Gradle 8.13（含官方 SHA-256）、AGP 8.11.1、Kotlin/Compose 编译插件 2.2.21、compile/target SDK 36、minSdk 初始值 26、Build Tools 35.0.0、command-line tools 13114758。

选择依据为 Android 官方 AGP 8.11 兼容表（Gradle 8.13、JDK 17、最高 API 36）和 Kotlin 官方兼容表（2.2.20–2.2.21 支持此 Gradle/AGP 组合）。这是固定兼容基线，不声称是最新版本。Compose UI/Media3 等应用依赖在实现时精确锁定，不能直接照搬上游依赖并假定支持本基线。

依据：`https://developer.android.com/build/releases/past-releases/agp-8-11-0-release-notes`、`https://kotlinlang.org/docs/gradle-configure-project.html`、`https://services.gradle.org/distributions/gradle-8.13-bin.zip.sha256`。

Actions 固定到完整 commit SHA。Ubuntu 标签、SDK 包修订与 runner 预装工具可能更新，因此该方案统一主要工具版本，不承诺字节级可复现；每次记录实际环境、依赖和产物 SHA。未来依赖引入时补齐 Gradle 锁文件和依赖校验元数据。

## 2. Actions 职责与目标约定

| 流程 | 触发 | 职责 |
| --- | --- | --- |
| `Cloud build` | main/contribution push、PR、手动 | 日常文档/政策检查；完整 Android 工程接入后运行单测、lint、Debug APK、版本/签名验证和产物上传；不发布 Release |
| `Trusted PR policy` | 面向 main/contribution 的 PR，使用 `pull_request_target` | 仅使用固定 base SHA 的受信任策略与只读 API，拒绝受限路径变更并检查提交身份；不执行 PR 代码 |
| `Bootstrap cloud toolchain` | 所有者在 main 手动触发 | 在云端安装固定环境并生成 wrapper，作为未来工程输入；不创建业务功能或 APK |
| `Owner release` | OnlineMo 在 main 手动指定版本 | 验收门槛 → detached 版本快照 → Release 单测/lint/编译/校验 → 仅推送新 tag → 发布 Release |

缺少 Android 工程时，Cloud build 只能报告“仅规划/配置检查”，不能声称 Android 构建通过或生成 APK；一旦存在 `android/`，缺失 wrapper、settings 或 app 构建脚本必须报错。Release 缺少应用或验收证据时必须失败。目前尚无应用构建或设备验收结果。

所有 PR，包括所有者 PR，都禁止新增、修改、删除或重命名 `version.properties`、`.github/workflows/`、`.github/actions/` 下的文件；重命名检查原、新路径。可信 policy 只读 API，不能 checkout 或执行 PR head/合并结果；无法完整检查的变更拒绝。PR 编译单独使用 `pull_request`，不提供签名或发布 secrets。

Actions 变更通过 Actions Issue 申请，由所有者审阅后以本人认证直接在 PR 之外维护；没有专用维护工作流。必要时临时调整保护，维护后立即恢复、验证并记录，详见 [治理要求](10-仓库治理与发布.md)。

## 3. 版本、签名与发布隔离

main/contribution 的 `version.properties` 始终逐字节保留开发版本 **0.0.0 / 0**，发版后也不变。`scripts/ci/check.py` 必须在所有普通 PR、push、手动构建中比较 [固定完整字节](10-仓库治理与发布.md#2-开发版本与可信-pr-检查)，包括注释、无 BOM、LF 与末尾换行。普通 Debug 版本因此恒定；产物由 source SHA、build SHA 和 Actions run 区分，不能用应用版本判断构建先后。

可信分支 Debug 使用稳定的 `.dev` 包名及独立 Debug 证书，Release 使用正式包名及独立 Release 证书；两者指纹固定在 [签名证书指纹](../.ci/signing-certificates.json)。PR 使用临时调试证书且无 secrets，不要求匹配稳定证书。签名不同不能直接覆盖安装，也不自动卸载或删除数据来绕过；需要稳定签名验收包时使用已审阅分支的云端产物。

两张证书已独立生成，采用 RSA 3072、SHA-256、30 年有效期；主题和恢复约定见 [签名与恢复](10-仓库治理与发布.md#4-签名secrets-与私有恢复)。签名 secrets 按仓库级配置，当前私有套餐的 environments 可能不支持；证书和指纹存在不等于 secrets 已部署或工作流已验证，实际状态以 13 文档为准。

Release 独立于日常 Cloud build：从已审阅 main SHA 创建 detached 快照提交，差异仅为版本文件。versionCode 为所有既有精确 `v<major>.<minor>.<patch>` 发布 tag 中最大 versionCode 加 1（无 tag 时为 1），新 SemVer 必须递增并高于所有既有发布版本。快照校验独立于普通开发文件固定值检查；实际 APK 必须匹配快照中的版本。

发布只能使用该次运行的短期 `GITHUB_TOKEN` 推送全新不可变 tag、上传附件和发布 Release，绝不推送 main/contribution，也不将快照合并回去。不使用 deploy keys。并发、完整 tag 枚举与失败恢复要求见 [发布流程](10-仓库治理与发布.md#3-目标发布流程只创建快照-tag)。首次公开 0.1.0 prerelease 还需 P0–P3、全部证据与用户批准；1.0.0 需 P0–P5。

## 4. 未来工程接入约定

`android/` 是 Gradle 根目录；模块为 `:app`；主 flavor 名为 `watchAndroid`，Debug 包名加 `.dev`，Release 不加该后缀。任务固定为 `testWatchAndroidDebugUnitTest`、`lintWatchAndroidDebug`、`assembleWatchAndroidDebug`，Release 使用对应 Release 任务。

初始化 wrapper 必须在云端运行 `Bootstrap cloud toolchain`，下载其 wrapper 产物后放入 android，不能在本地运行 `gradle wrapper`。wrapper 属性中的 URL/校验值必须与基线一致。

未来 `android/settings.gradle.kts` 需要在 pluginManagement 中读取 `../.ci/toolchain.properties`，给 Android、Kotlin Android 和 Kotlin Compose 插件设置版本。在 settings 中加入：

```kotlin
check(System.getenv("GITHUB_ACTIONS") == "true" && System.getenv("CI") == "true") {
    "Android builds run in GitHub Actions. Edit locally and download the cloud APK."
}
```

此约定也会阻止本地 Gradle sync；本地使用编辑器完成文本编辑，编译诊断从云端获取。不把设置环境变量冒充 CI 当作本地编译许可。

app 脚本从根目录上一级读取工具链和版本 properties，设置 compileSdk、buildToolsVersion、minSdk、targetSdk、versionName、versionCode；Release 先生成 unsigned APK，正式签名在独立云端步骤完成。禁止 flavor、buildType 或输出重写版本。CI init script 校验 Gradle/AGP/SDK/defaultConfig，打包后再次读取 APK 内实际版本与包名：普通 Debug 必须为 0.0.0 / 0 且带 `.dev`，Release 必须等于发布快照且不带该后缀。应用级依赖统一放在 version catalog，禁止动态版本和浮动 Git 分支依赖。

## 5. 本地操作边界

本地可以编辑、进行已授权的 Git 操作、脚本/政策检查、校验下载文件，以及 adb 安装、抓取脱敏日志和设备验证。本地不执行 Android 编译、Gradle 单测/lint、Kotlin/Java 编译或 Android Studio Build/Run。低影响文档改动只需核对内容和链接，不要求应用测试。

签名密钥管理不属于应用编译。私钥和密码不得进入本项目；用户已单独授权的 p12、明文密码及恢复元数据仅可存入独立、永久私有、关闭 Actions 且无协作者的恢复仓库。此处不记录其名称、地址或凭据。

示例（仅在已经下载正确产物并连接目标设备后）：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'artifacts/app-watchAndroid-debug.apk'
adb devices -l
adb -s '<手表序列号>' install -r 'artifacts/app-watchAndroid-debug.apk'
```

安装前逐项比对 `SHA256SUMS` 和 `build-manifest.json`，并确认 source/build SHA 对应本次改动。PR 记录 head SHA 与实际合并结果的 build SHA；发布记录 main 源 SHA 与快照 SHA。记录版本、签名指纹和 run，不以恒定的 Debug 版本代替产物身份。

## 6. 产物和失败处理

产物保留约定为：Debug artifact 14 天，测试报告 7 天，Release 构建 artifact 30 天，GitHub Release 附件长期保留。产物包括 APK、版本/签名/工具链/提交/run 信息 manifest 和 SHA256SUMS。云端任务不自动完成设备测试，必须另附实机记录。

PR 失败：修改本地代码后重新云端构建。工具链失败：由所有者修复基线，不切回本地编译。云端 API/配额不可用：记录阻断，不声称构建通过。发布 tag 创建前失败不产生新发布点；tag 已创建而 Release API 失败时，保留 tag 与已签名产物，由所有者恢复同一 Release，不删除或覆盖 tag、不重用版本号、不替换为不同快照。整个发布过程都不回写开发分支。
