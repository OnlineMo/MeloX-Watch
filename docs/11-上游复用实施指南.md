# 上游复用实施指南

目标是用已经验证的上游业务减少实现量，同时避免上游变更与本地实现混用。

## 固定来源

机器可读依据为 `.ci/upstream-lock.json`。Android 基线为 `83632b17e1ee857bc428134528e0fd86c5fd4d01`，Apple/Watch 基线为 `09713edb847a0f0a3515a34f779cc630d4fe5985`。禁止参考浮动 main/latest URL 做实现；网页审阅使用带完整 commit 的 blob URL，本地使用 detached HEAD。

本地快照不加入产品 Git 仓库，也不在云端构建时从上游自动拉最新。新开发者下载时按锁文件 URL 初始化仓库，fetch 指定 SHA，再 checkout --detach 指定 SHA，运行 `python scripts/ci/check-upstreams.py`。未下载快照时 CI 只检查锁文件；存在时必须同时满足 SHA 正确、detached、无修改。

## 推荐迁移顺序

| 批次 | 直接复用候选 | 需自行完成 |
| --- | --- | --- |
| R1 模型与解析 | MusicModels 的必要字段、LRC 时间解析、音质/可用性判断 | 精简模型边界、测试数据、与 UI 解耦 |
| R2 网易云客户端 | 搜索、歌单、日推、账号校验、EAPI/WEAPI 请求构造 | 注入会话和 HTTP；移除远程脚本耦合；补齐真实分页/错误/取消 |
| R3 播放行为 | Android 焦点、耳机断开、队列持久化的逻辑 | 精简 Media3 服务、状态机和圆屏控制器；不整体搬手机 Service |
| R4 手表交互 | Apple Watch 三页布局、扫码状态、队列语义 | Compose 圆屏实现；平台输入和存储重写 |
| R5 离线 | Android 下载资源解析和任务索引思路 | 独立持久下载库、URL 更新、完整性/恢复；不用 Watch 临时文件冒充下载 |

首发不迁移插件、多音源、AutoMix、手机 OEM 通知和重型视觉资源。每个批次先得到一个小型可用闭环并云端验证，再增加下一批，避免先复制大量代码再难以裁剪。

## 每个迁移任务的记录

在对应 PR 和后续 `docs/upstream-migrations/` 记录：来源仓库、完整 SHA、文件路径、许可；直接/传递依赖；保留行为与主动修改；新增/复用测试；云端 run 和本地设备证据。不要凭“来自上游”省略测试，因为手表的系统、性能和依赖均不同。

## 升级上游的独立流程

1. 为升级单独开 Issue，写明目的、当前 SHA、候选 SHA，不直接覆盖 research 快照。
2. 在 `.local/upstream-candidates/` 独立获取候选版本；对比已复用的文件、接口、模型、许可证和依赖。
3. 列出本地每个迁移批次受影响的地方，尤其是登录参数、歌曲 ID、缓存 key、下载状态和错误语义。
4. 在专门分支修改本地实现和契约样本，云端编译/单测/lint，本地回归关键路径。
5. 所有者在同一 PR 更新锁文件、迁移记录和必要文档，说明无需迁移的上游变化。全部通过后合并。
6. 最后把本地 research 切到新锁定 SHA，再运行一致性检查。旧来源记录保留以便追溯。

候选升级失败时继续使用旧基线，不能出现“新代码按最新上游写、旧代码仍按旧上游跑”的隐式混用。自动依赖更新机器人不修改上游源码锁。
