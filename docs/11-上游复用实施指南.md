# 上游复用实施指南

多平台接口参考遵守 [18 扩展约定](18-多平台音源接口与扩展约定.md)：固定 Android 上游的 `MusicProvider.kt` 可供细分能力设计参考，不能整体移植多平台注册/动态插件和全部 SDK。QQ 音乐仅为以后可审阅的适配候选；咪咕接口另行调研，不因预留而改变固定上游或首发范围。

目标是用经静态审阅的上游业务逻辑减少实现量，同时避免上游变更与本地实现混用。源码审阅不等于在 Watch X2 上验证通过；当前无 Android 实现、APK 或运行结果。

## 固定来源

机器可读依据为 `.ci/upstream-lock.json`。Android 基线为 `83632b17e1ee857bc428134528e0fd86c5fd4d01`，Apple/Watch 基线为 `09713edb847a0f0a3515a34f779cc630d4fe5985`。禁止参考浮动 main/latest URL 做实现；网页审阅使用带完整 commit 的 blob URL，本地使用 detached HEAD。

本地快照不加入产品 Git 仓库，也不在云端构建时从上游自动拉最新。新开发者下载时按锁文件 URL 初始化仓库，fetch 指定 SHA，再 checkout --detach 指定 SHA，运行 `python scripts/ci/check-upstreams.py`。未下载快照时 CI 只检查锁文件；存在时必须同时满足 SHA 正确、detached、无修改。

## 推荐迁移顺序

| 批次 | 直接复用候选 | 需自行完成 |
| --- | --- | --- |
| R1 模型与解析 | MusicModels 的必要字段、LRC 时间解析、音质/可用性判断 | 精简模型边界、测试数据、与 UI 解耦 |
| R2 网易云客户端 | 搜索、歌单、日推、账号校验、EAPI/WEAPI 请求构造 | 注入会话和 HTTP；移除远程脚本耦合；补齐真实分页/错误/取消 |
| R3 播放行为 | Android 焦点、耳机断开、队列持久化的逻辑 | 精简 Media3 服务、状态机和圆屏控制器；不整体搬手机 Service |
| R3-L 本地音乐（P2-L） | `core/provider/local` 的字段、MediaStore/SAF 调用、元数据/LRC 关联、播放列表操作和 URI 解析思路 | Room 增量索引、全局有界扫描、授权/取消/移位恢复、真正分页、按需封面、本地无网络边界；接入 R3 单播放器 |
| R4 手表交互 | Apple Watch 三页布局、扫码状态、队列语义 | Compose 圆屏实现；平台输入和存储重写 |
| R5 在线下载（P4） | Android 下载资源解析和任务索引思路 | 独立持久下载库、URL 更新、完整性/恢复；与 P2-L 用户文件曲库分开，不用临时缓存冒充下载 |

首发不迁移插件、多音源、AutoMix、手机 OEM 通知和重型视觉资源。每个批次先得到一个小型可用闭环并云端验证，再增加下一批，避免先复制大量代码再难以裁剪。

R3-L 在 P1 共享基础和 DEV-005 探针后，可与在线 P2 并行，属于首个 `0.1.0` prerelease 必需范围；不等待 P4。性能、界面和代码分别执行 [14](14-性能优先与资源预算.md)、[15](15-界面设计与视觉验收.md)、[16](16-代码规范与可读性.md)。

## 本地模块的固定源码审阅

下表仅审阅 Android 锁定提交 `83632b17e1ee857bc428134528e0fd86c5fd4d01`，路径前缀为 `android/app/src/main/kotlin/com/lladlam/melox/core/provider/local/`。4 个文件合计 **728 行**，含空行和注释，不包括 `LocalRecognitionCoordinator.kt`、手机 UI、播放器或传递依赖；不是可直接移植的完整功能规模。完整固定 SHA URL 见 [17 的来源表](17-本地音乐功能与实施计划.md#11-固定来源与官方参考)。

| 文件 | 行数 | 已看到的行为 | 手表迁移约束 |
| --- | --- | --- | --- |
| `LocalModels.kt` | 36 | 本地曲目、URI 根与播放列表模型 | 拆开逻辑身份/访问 URI/账号；不迁入在线识曲字段依赖 |
| `LocalMediaScanner.kt` | 221 | MediaStore 查询、SAF 目录递归、元数据和同名歌词读取、内嵌封面提取 | 递归为目录/文件建 async，每层 `Semaphore(4)` 不构成全局上限；扫描后为缺图曲目批量建任务提图；须改为全局并发初始 1、分批增量和按需降采样 |
| `LocalMusicRepository.kt` | 279 | SharedPreferences 保存 tracks/playlists/roots JSON，收藏及歌词/封面更新 | `tracks()` 全量解析，修改常经 `replaceTracks()` 整体重写；改为 Room 按项/批量事务与真实分页，验证收藏读写正确性，不复制整库 JSON |
| `LocalProvider.kt` | 192 | 本地检索、播放列表 CRUD/重排、收藏入口、URI 播放资源解析 | 搜索先取全库再切页；URI 直接返回不能证明授权/文件仍有效；识别 ID 可触发 `AmlldbLyricsClient` 联网回退，首版本地必须移除该依赖 |
| 合计 | **728** | 静态源码证据 | 没有构建、运行或 Watch X2 性能结论 |

扫描失败/取消不得替换为成功空库；完整来源扫描成功后才按 generation 标记缺失，保留收藏、列表和历史。URI 别名去重须有来源身份依据，相同元数据不等于同文件；移动后的重关联保留稳定逻辑 ID。首发不引入外部原文件物理删除、Wi-Fi 传歌、标签编辑、CUE、额外解码器或 DRM 解密。

新增本地生产代码约 3–6 千行、测试约 1–2 千行，是相对于未来共享基础的粗估，当前实现仍为 0；不能以 728 行上游源码推断只需复制即可交付。任务 DEV-005、DEV-211–218、8–12 人日增量及验收在 [05](05-开发阶段与任务清单.md) 与 [17](17-本地音乐功能与实施计划.md) 定义。

## 每个迁移任务的记录

在对应 PR 和后续 `docs/upstream-migrations/` 记录：来源仓库、完整 SHA、文件路径、许可；直接/传递依赖；保留行为与主动修改；新增/复用测试；云端 run 和本地设备证据。不要凭“来自上游”省略测试，因为手表的系统、性能和依赖均不同。

## 升级上游的独立流程

1. 为升级单独开 Issue，写明目的、当前 SHA、候选 SHA，不直接覆盖 research 快照。
2. 在 `.local/upstream-candidates/` 独立获取候选版本；对比已复用的文件、接口、模型、许可证和依赖。
3. 列出本地每个迁移批次受影响的地方，尤其是登录参数、歌曲 ID、缓存 key、下载状态和错误语义。
4. 在专门分支修改本地实现和契约样本，云端编译/单测/lint，本地回归关键路径。
5. 所有者在同一 PR 更新锁文件、迁移记录和必要文档，说明无需迁移的上游变化。全部通过后合并。
6. 最后把本地 research 切到新锁定 SHA，再运行一致性检查。旧来源记录保留以便追溯。

候选升级失败时继续使用旧基线，不能出现“新代码按最新上游写、旧代码仍按旧上游跑”的隐式混用。自动依赖更新机器人不修改上游源码锁。
