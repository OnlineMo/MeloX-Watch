# 上游复用实施指南

通用接口参考遵守 [18 接口预留](18-通用音源接口预留.md)：固定 Android 上游的 `MusicProvider.kt` 可供当前所需小接口设计参考，不能整体移植多平台注册/动态插件和全部 SDK。未来实际采用的来源及接口届时评估，不因上游支持某个平台就预定本项目的接入列表。

目标是为普通 Android 智能手表复用必要业务逻辑，避免上游变更与本地实现混用。Watch X2 仅为当前主测设备，不迁入机型白名单或 OPPO 运行假设；当前无 Android 实现、APK 或任何手表运行结果。

## 固定来源

机器可读依据为 `.ci/upstream-lock.json`。Android 基线为 `83632b17e1ee857bc428134528e0fd86c5fd4d01`，Apple/Watch 基线为 `09713edb847a0f0a3515a34f779cc630d4fe5985`。禁止参考浮动 main/latest URL 做实现；网页审阅使用带完整 commit 的 blob URL，本地使用 detached HEAD。

本地快照不加入产品 Git 仓库，也不在云端构建时从上游自动拉最新。新开发者下载时按锁文件 URL 初始化仓库，fetch 指定 SHA，再 checkout --detach 指定 SHA，运行 `python scripts/ci/check-upstreams.py`。未下载快照时 CI 只检查锁文件；存在时必须同时满足 SHA 正确、detached、无修改。

## 推荐迁移顺序

先按09/20完成 DEV-004-A 云端最小探针，供 DEV-002/003/005 核验，再由 DEV-004-B 建基线；下列迁移在同一 `:app` 内按职责包逐步扩充，不先创建空Gradle模块；LP-14按明确的手机产品边界增加真实模块。计划包名与依赖锁以03/09为准，上游包名、凭据及安全配置不直接沿用。

上游复用首发不迁移插件、完整多平台 SDK、AutoMix、手机 OEM 通知和重型视觉资源；这只表示不直接搬入这些上游实现或资源，不表示删除本项目已确认的功能。LP-07/12仍必须实现歌词、字体、主题、背景和显示效果，LP-13/14仍必须交付传输与真实手机配套；使用本项目独立审查的实现和资源。每批先得到小型闭环并云端验证，再增加下一批。

R3-L 在 P1 共享基础和 DEV-005 探针后，可与在线 P2 并行，属于首个 `0.1.0` prerelease 必需范围；不等待 P4。性能、界面和代码分别执行 [14](14-性能优先与资源预算.md)、[15](15-界面设计与视觉验收.md)、[16](16-代码规范与可读性.md)。

## 每个迁移任务的记录

在对应 PR 和后续 `docs/upstream-migrations/` 记录：来源仓库、完整 SHA、文件路径、许可；直接/传递依赖；保留行为与主动修改；新增/复用测试；云端 run 和本地设备证据。不要凭“来自上游”省略测试，因为手表的系统、性能和依赖均不同。

## 升级上游的独立流程

1. 为升级单独开 Issue，写明目的、当前 SHA、候选 SHA，不直接覆盖 research 快照。
2. 在 `.local/upstream-candidates/` 独立获取候选版本；对比已复用的文件、接口、模型、许可证和依赖。
3. 列出本地每个迁移批次受影响的地方，尤其是登录参数、歌曲 ID、缓存 key、下载状态和错误语义。
4. 使用独立迁移工作区/checkout修改本地实现和契约样本；在该工作区同时更新锁文件及对应research快照到候选SHA，再运行固定引用检查。日常工作区保持旧锁＋旧快照，不能先改锁却用旧快照跑检查，也不能让日常开发抢先参考新代码。
5. 云端编译/单测/lint，本地回归关键路径；所有者在同一PR提交实现、锁、来源/迁移记录和必要文档，说明未受影响的变化。候选快照仍不入产品Git。
6. PR通过并合并后，其他工作区才同步新锁和对应research快照，重新核对clean detached HEAD。旧来源SHA保留在迁移记录与Git历史；不删用户修改、不用失败的新基线覆盖旧工作。

候选升级失败时继续使用旧基线，不能出现“新代码按最新上游写、旧代码仍按旧上游跑”的隐式混用。自动依赖更新机器人不修改上游源码锁。
