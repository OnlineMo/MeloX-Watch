## 2. 视觉方向与阶段交付

视觉方向是黑底、薄荷绿强调、安静的静态封面和清晰的音乐层级。先辨认“这是什么歌、现在是什么状态、按哪里”，然后才注意到装饰。每个当前任务只有一个最高强调的动作；次级操作使用中性色行项或图标，不堆叠同等强度的大色块。

| 阶段 | 设计交付 | 可审查结果与退出条件 |
| --- | --- | --- |
| P0 | 实机窗口与字体记录、系统输入/返回/无障碍能力记录 | 明确实际 dp、圆形边界、inset 和不可用能力；未知项如实填写；不凭分辨率宣传页推导已适配 |
| **P1** | **颜色/字阶/间距令牌，播放主按钮、列表行、状态提示的组件样例**；静态封面/长标题播放器、本地入口、扫描部分完成及导入副本删除确认样例 | 先检查默认、按下、缓冲、不可用、大字体和紧凑替代布局；检查 docs14 的相应性能项。此阶段就修正视觉方向，不把美观和基本组件一致性推迟到 P3 |
| P2 | 登录与在线列表状态；本地分类、搜索/排序、收藏、播放列表管理、扫描/权限/文件错误样例 | 测试数据之外补充实际业务结果；本地入口不依赖账号；主动作、分页和错误恢复不跳位；不以成功态单图代替状态设计 |
| **P3** | **`0.1.0` 完整本地＋在线页面及状态**，包含本地音乐独立页、完整本地管理、共用播放器/队列/歌词、在线列表/搜索/登录、异常恢复 | Watch X2 上完成第 9 节矩阵、两条核心路径、截图、短录屏和 docs14 回归记录；关联 docs06 在线适用用例、T-23–T-31 本地专项及 docs17。本地仍有必需项未测时不能只凭在线闭环放行 |
| P4/P5 | 范围内后续在线下载管理与最终收敛 | 新组件沿用令牌，新增功能重复相关矩阵；首发本地能力不能推迟至此，已测本地播放也不能证明在线下载或全固件能力 |

P1 的样例可先作静态设计审查，但静态样例只证明设计内容存在；任何“已在设备通过”结论都必须绑定未来真实产物和实际设备记录。

## 3. 颜色与静态对比度

### 3.1 初始颜色令牌

颜色均按不透明 sRGB 定义，不在整组文字或按钮上统一降低透明度。封面中的颜色不得自动取代语义色，不在专辑图上直接压正文。黑底是视觉选择，不能据此宣称耗电达标。

| 令牌 | 初始值 | 用途及限制 |
| --- | --- | --- |
| `background` | `#000000` | 页面底色 |
| `surface` | `#151A17` | 必要的按钮/状态区域；列表不必逐项做卡片 |
| `surfacePressed` | `#263A30` | 次级区域按下态，几何尺寸不变 |
| `textPrimary` | `#F2F7F4` | 歌名、正文、关键状态 |
| `textSecondary` | `#B7C6BD` | 艺人、时长、说明；不可用于隐藏重要错误 |
| `accent` | `#8DE6C0` | 唯一主按钮底、当前项标记、焦点；不是所有标签的默认色 |
| `onAccent` | `#082419` | 薄荷色按钮上的图标/文字 |
| `accentPressed` | `#6ECBA3` | 主按钮按下底色 |

| `disabledText` | `#95A29A` | 禁用状态文字，搭配“暂无上一首”等原因和禁用语义 |

### 3.2 已计算的默认配色，不是设备测量

依据 W3C 相对亮度定义 [R3]，将每个 8 位通道除以 255 得到 `c`：`c <= 0.04045` 时线性值为 `c/12.92`，否则为 `((c+0.055)/1.055)^2.4`；`L = 0.2126R + 0.7152G + 0.0722B`；对比度为 `(L较亮+0.05)/(L较暗+0.05)`。以下为 2026-11-10 对上述十六进制值直接进行的数值计算，显示两位小数；判定使用未舍入值。未测量面板亮度、抗锯齿、截图像素或环境光。

项目将**所有有意义的文字均按至少 4.5:1**审查，不使用“大字可以降低要求”的例外；必要控件图形、轮廓及状态标记按至少 3:1 审查 [R1][R2]。这些是本项目采用的设计检查尺度，不构成整款原生应用的 WCAG 合规认证。

## 4. 字体、间距与触控组件

### 4.1 字阶建议

默认使用系统字体和系统字形回退；不捆绑装饰字体或为强调而压缩字宽。文字尺寸使用 sp，几何尺寸使用 dp；Android 字体缩放可能非线性，不能用 `sp × fontScale` 推定全部实测高度 [R4][R5]。下表行高为起点，应给实际字形、emoji 和放大后的文字留足空间。

| 用途 | 初始字号 / 行高 | 字重与排版 |
| --- | --- | --- |
| 歌名/页面主标题 | 18sp / 24sp | Medium；播放器居中，列表左对齐；摘要最多两行 |
| 当前歌词 | 20sp / 28sp | Medium；优先保留完整当前行，长句换行 |
| 正文/列表名称/动作标签 | 16sp / 22sp | Regular 或 Medium；列表行随内容增高 |
| 艺人/上下文歌词/说明 | 14sp / 20sp | Regular；不靠透明度降低重要性 |
| 非关键时间/数量摘要 | 12sp / 16sp | Regular；不能用于关键错误、登录步骤或主操作 |

标题省略发生在完整字素边界，不能拆散 emoji、变音符号或组合序列。中英文混排、无空格长英文、数字和标点均应测量后换行。只有摘要标题可省略；完整名称通过可访问的曲目详情行查看。错误原因、恢复步骤、登录说明不能仅提供不可展开的省略号。默认无跑马灯、逐字跳动或字重呼吸动画。

### 4.2 尺寸令牌建议

| 用途 | 初始值 | 适配规则 |
| --- | --- | --- |
| 间距步进 | 4 / 8 / 12 / 16dp | 同类组件统一使用；大字体可增高容器，不能减少触控底线 |
| 圆边视觉/触控附加安全距 | 8dp 起步 | 叠加实际系统避让，实测可增大；不是通用设备保证 |
| 普通触控区域 | **至少 48 × 48dp** | 图标可小于区域；整个区域必须可触达且无重叠 [R4] |
| 主操作区域（含播放/暂停、保存、确认） | **至少 56 × 56dp** | 圆按钮或更宽的有标签按钮均可；字体放大时扩容；本地管理页同样适用 |
| 相邻独立触控区域间距 | 8dp 起步 | 圆内放不下则改布局，不能通过重叠透明热区凑数 |
| 图标视觉尺寸 | 24dp；主播放图标 28dp | 保持光学对齐，不能把视觉尺寸当触控尺寸 |
| 列表行 | 最小 56dp 高，内容自适应 | 多行文字、字体放大时增加高度；整行可点，不叠放同动作的小按钮 |
| 区域圆角 / 边线 | 12dp / 1dp 起步 | 焦点环可用 2dp；须计入几何边界 |
| 封面 | 48dp 起步；有余量可用 64dp | 服从整页实际排布；空间不足先移除封面，不能压缩主操作 |

### 4.3 组件共用规则

- **主按钮**：薄荷底、深色符号；播放与暂停语义跟随真实播放器状态。按下改变底色，松开恢复，不放大触控区域、不推移相邻内容。处理中可显示静态状态符号和“缓冲中”，仍提供符合实际能力的暂停/取消动作，不能伪造“已播放”。
- **列表行**：名称在先，艺人/数量在后；最多一个当前项图标和必要状态短语。当前项用图标/文字加颜色，不能只有绿色。返回列表保留位置；有无缩略图时文字起点和行高规则一致。
- **状态提示**：紧邻所属内容，先说明结果，再给一个主要恢复动作；短横幅不遮住主播放控件。状态变化不反复抢焦点、不每次进度更新都播报。
- **封面**：静态、等比裁切、单一占位样式；加载中、缺图和下载失败保持原尺寸。新曲无封面时用占位图形，不能把旧曲封面冒充新曲。已展示内容的同曲刷新失败可保留封面。解码尺寸和缓存限额引用 docs14。
- **可访问语义**：提供按钮名称、角色、选中/禁用/忙碌状态和合理焦点顺序 [R4]。不重复朗读已有标题与装饰封面；切换页面后焦点有明确起点。辅助服务是否存在以该固件实际能力为准，不假定 GMS 或 TalkBack 已安装。

## 5. 圆形几何、实际 dp 与替代布局

### 5.1 先记录实际坐标

记录窗口宽高 px、系统报告的 density、实际换算 dp、fontScale、窗口在屏幕上的位置，以及状态栏/导航栏/显示缺口/手势保留区/输入法 inset。dp 换算用 `px / density` [R5]；不得由标称屏幕分辨率、物理尺寸或机型名称猜 density。应区分完整圆屏直径、当前窗口和扣除 inset 后的可用区域，不将“内容宽度 220dp”直接当作“圆屏直径 220dp”。

系统 inset 影响内容可见和操作区域 [R6]。以实测圆屏中心、半径及窗口偏移统一坐标；圆形信息不可得时记录几何估计依据并现场校验。输入法弹出后窗口可能缩小，但不能据此重建一个虚假的小圆。实际系统返回手势区另行避让并验证，不能只检查图形是否在圆内。

### 5.2 校验整个矩形，不只校验中心点

下面是项目的保守布局推导，不是设备实测：圆心 `(cx,cy)`，实际半径 `r`，额外安全距 `m`，`R=r-m`。先取得已避让系统遮挡的可用矩形 `[Lw,Tw,Rw,Bw]`。对于一行的**完整触控/文字/焦点矩形**，顶部 `y0`、底部 `y1`：

1. 要求 `y0 >= Tw`、`y1 <= Bw`，并计算 `d=max(abs(y0-cy),abs(y1-cy))`。
2. `d >= R` 时不能放入有宽度的内容；否则 `h=sqrt(R²-d²)`。
3. 左边界为 `max(Lw,cx-h)`，右边界为 `min(Rw,cx+h)`；整行宽度和全部触控区域必须落在二者之间。非矩形遮挡另求交集。
4. 焦点环、按下态、文字字形及阴影若存在也计入外接矩形；不能只用行中心处弦宽。不能让被圆切掉的部分仍接收“隐形点击”。

**校验例**：假设圆屏直径 192dp、无 inset、`m=8dp`，位于圆心的 56dp 高行可用宽度为 `2×sqrt(88²−28²)≈166.85dp`。上一首 48dp、间隔 8dp、主键 56dp、间隔 8dp、下一首 48dp，共 168dp，**按本规范的保守整行矩形策略判为不适配**，应改布局。此结论针对整行外接矩形，不能推广为任何逐控件几何方案都不可能放下。直径 240dp 的相同中心行约 216.89dp，仅说明这行有机会放下，不证明整页适配。

**240dp、fontScale=1.0、无 inset 的探索草图**：以左上为原点，48dp 封面放在 `y=24…72`；标题先尝试 `y=80…104`、艺人 `y=108…128`；168dp 宽控制行放在 `y=136…192`，该行保守可用弦宽约 171.58dp；时间摘要放在 `y=200…216`、宽不超过约 115.38dp。上述只演示逐行验算，使用假设行高；一旦标题换行、字体变化或 inset 不为零，重新排布，不能硬套这些坐标。音乐菜单作为明确可滚动到中央的入口，不塞入剩余圆角。

### 5.3 布局选择与失败后的替代

| 触发条件 | 替代布局 | 仍须成立的条件 |
| --- | --- | --- |
| 三键横排整块区域不适配 | 主播放键居中；上一首/下一首移至明确的“播放控制”单列页或滚动区域 | 56dp 主键、48dp 次键不缩小；无需表冠也能到达 |
| 标题和封面挤压主操作 | 先移除封面/页点/非关键时长，再把艺人等移入曲目详情 | 首次进入仍可辨认曲目摘要、播放状态与主操作；完整曲名可查看 |
| 1.5/2.0 字体下单屏容不下 | 采用单列、增高行或分步页面；首屏保留主操作，完整标题/说明在可滚动详情；主操作不得与滚动文字重叠 | 不强制降低系统字体，不裁切关键动作，不只用图标替代必要说明 |
| 列表顶/底行落入窄弦 | 端部留白使第一/最后一项能滚到中央；边缘项可作为预览 | 点击和辅助焦点均能使完整行进入安全区；大行可展开详情，不能只有被裁切的可点击片段 |
| 输入法占用大部分视口 | 进入独立输入页，提交/关闭输入法后回到结果 | 查询保留，返回规则明确，系统 IME 不可用时有可理解反馈 |
| 二维码及说明无法共存 | 扫码页只保留完整二维码及静区；说明/刷新放在相邻单列步骤 | 不裁二维码、不缩静区；若扫码仍失败则登录未通过，不能靠设计图放行 |
| 本地管理动作、重排或删除确认放不下 | 列表行只负责进入详情/编辑；重排、来源说明、删除确认各用独立单列页 | 重要文件名、对象类型和后果可完整查看；保留安全取消，不靠微小行尾图标或长按作为唯一入口 |

列表、滚动歌词和详情可以超出一屏，但每条内容都应有完整可读位置。滑动分页从内容区开始；边缘返回遵循系统行为。表冠只作可选增强，所有任务必须有触控路径。没有证据时，不声明某一紧凑模式已解决 2.0 字体适配。

## 6. 页面规格

以下是未来实现需满足的可观察行为；未实现功能不展示假入口。每页的“主动作”指当前任务唯一最高强调动作，常规返回/关闭仍保留。切换任务阶段可以改变主动作，但不能同时摆放多个同权重的薄荷色大按钮。

### 6.1 正在播放

- **来源与入口**：本地与在线共用播放器及队列/歌词页；曲目详情清楚标识来源，必要时在摘要显示“本地”。“选择音乐”进入含“本地音乐”“在线音乐”的选择页，本地入口始终可用；本地未扫描时引导选择来源或扫描，不能跳登录。不要把分类、收藏、排序和删除按钮铺在主播放页上。
- **内容顺序**：静态封面 → 曲名/艺人 → 播放状态与主播放键 → 时间概要 → 次级控制入口。主键优先于封面占用空间。视觉顺序与可访问阅读顺序一致；实际窄屏按第 5 节移走装饰和次级内容。
- **主动作**：有歌曲时播放/暂停；真正无歌曲时改为“选择音乐”。有歌曲时进入音乐菜单是次级操作；进度、音量、模式进入独立控制页，不放一圈难以命中的微小控件。进度概要不伪装成可拖动的细圆环。
- **状态**：解析中、缓冲中、播放中、已暂停、耳机断开已暂停、不可播放分别给出短语。按下状态立即反映已接收操作，最终状态仍由播放器确认。缓冲不循环闪烁封面；音频未出声不能标记为播放成功。
- **切歌**：立即展示目标歌曲及其占位封面；不能让旧请求回写标题/歌词。错误发生时保留目标曲名、队列和已知进度，指明“重试”或“选择其他歌曲”；不清空成欢迎页。不可重试时不给无效重试按钮。
- **恢复**：退后台、熄屏、重建后回到同一播放会话；曲名、进度和按钮从当前快照恢复，不能先播一次动画或生成第二个会话。详情显示完整标题，支持返回原位置。
- **页内验收**：按下/快速连点/切歌后失败/封面缺失/耳机断开均录下状态顺序；大字体首屏主键无裁切，完整曲名可查看，最后一次用户意图不被旧回调覆盖。

### 6.2 队列

- 标题简短，数量可作为次级信息；当前曲目有静态播放/暂停图标和“当前”文字，其余行显示名称及艺人。默认不展示动画均衡器。
- 主任务是选择一首播放；整行可点，当前项承担视觉强调。模式和清空等操作放在独立菜单，不与行内切歌争夺点击区域；首发不依赖拖动排序。本地播放列表必须支持第 6.8 节的显式顺序编辑，不能用“不做拖动”省略重排能力；播放队列与持久播放列表的修改范围分别说明。
- 本地文件失效时保留曲名与来源并标记“找不到文件”或“访问权限失效”，给对应恢复入口；不伪装成联网缓冲。跳过失效项的上限及播放政策遵循业务约定，不无限跳转。修改本地列表排序或收藏不能无提示地替换当前队列。
- 切歌中保留列表与滚动位置，目标行显示处理中；失败标记留在目标行，并给恢复入口。空队列显示原因及“选择音乐”；不要把加载中、空队列、读取失败混成同一空白屏。
- 大队列按 docs14 控制可见对象、图片与分页资源；不能一次绘制全部内容。测试首项、末项、长标题和当前项在圆边处的完整可达性，返回后位置不丢失。

### 6.3 歌词

- 当前行使用主字阶和高对比色，上下文使用次级字阶；同时以位置/字重区分，不能只靠薄荷色。无逐字发光、渐变扫字、旋转或随音乐缩放。
- 长句允许换行；当前句高于可用区域时提供手动完整阅读，不把字号缩回默认值。翻译/附加歌词先作为可选详情，不能挤掉当前原文。
- 默认跟随当前时间；用户手动滚动后保持其阅读位置，显示唯一主要动作“回到当前”。触发后跳回或执行一次有界过渡；减少动态效果时直接定位。不要每次定时更新都重新滚动或打断辅助阅读。
- 无歌词显示“暂无歌词”及仍可使用的播放入口；请求失败给“重试”，已缓存歌词刷新失败保留内容并注明。解析异常、乱序时间戳、seek 和连续切歌均不得显示其他歌曲的歌词或影响播放。
- 本地曲目按 docs17 的关联规则读取获准访问的 LRC；详情标明“本地歌词”，无文件显示“暂无本地歌词”。LRC 损坏、编码/时间戳异常、权限失效或音频与歌词关联不匹配时说明原因，音频仍可播放；不为补齐歌词强制登录或联网。多份同名 LRC 不能任意串配，匹配不明确时保持缺省状态并提供实际可用的重新选择入口。封面缺失/损坏沿用固定尺寸的静态占位，不联网补图、不显示上一首封面；这不引入歌词/标签编辑器。
- 只在该页可见且屏幕亮起时进行必要跟随；更新粒度、偏差和性能标准引用 docs14。页面隐藏后即使仍挂在分页容器中，也不得运行歌词 UI 定时任务。

### 6.4 登录 / 二维码

- 初始说明简短，例如“用手机网易云音乐扫码”，明确手机只承担本步骤的扫码角色；实际登录方式由 P0 验证决定。生成中展示静态占位与文字，不用假二维码。
- 二维码采用黑模块、白底、无装饰覆盖和无裁切静区。DENSO WAVE 官方说明普通 QR Code 四周需要至少四个模块宽静区 [R8]；模块数、静区和实际输出尺寸一并记录，不能把四个模块误写成固定 4dp。
- 将**含静区的整个正方形**纳入圆内几何验算；圆心正方形理论边长不超过 `sqrt(2)×R`，还要满足实际窗口和 inset。像素模块应清晰、边界稳定，不由缩略封面控件插值模糊。上述几何只证明放得下，扫码可用性必须通过实际手机与手表验证。
- 等待扫码时二维码是核心内容，取消是次级操作；已扫码待手机确认时显示说明，不重复提供同等强调刷新。过期明确标为“二维码已过期”，主动作“刷新二维码”；网络失败给一次明确重试，已知失效的二维码不能继续显示为有效。
- 登录成功基于真实账号校验结果；退出后停止登录页轮询，旧二维码结果不覆盖新一轮。可见页轮询政策及超时引用 docs14/既有账号设计，不能靠倒计时动画制造轮询需求。无网络时保持步骤与原因，不清空整个流程。
- 大字体时把完整说明和扫码图分步显示。若所有安全布局下二维码仍无法稳定扫描，记为登录阻断；另行评估获准的替代登录范围，不伪称已有手机桥接方案。
- 录屏中的活跃二维码、账号信息和登录状态凭据按项目隐私规则处理。对外展示用失效或合成样本；合成图不能证明真实扫码通过，真实结果另留脱敏记录。

### 6.5 音乐菜单、歌单列表与详情

- 菜单每行只表达一个任务，采用固定文字起点和简洁图标；明确提供“本地音乐”和“在线音乐”两个入口，本地为独立页面，详见第 6.8 节。未登录直接进入本地库，仅在线功能提示登录；在线登录过期的提示不能遮挡本地入口。后续在线下载入口按实际范围展示，不能借此隐藏首发本地音乐入口。
- **音源选择**：依据 [18-多平台音源接口与扩展约定](18-多平台音源接口与扩展约定.md)，只展示真正实现且已启用的音源及其实际能力；首版计划为本地文件＋网易云在线。QQ 音乐、咪咕属于未来候选，不展示占位入口、假登录页或可播放承诺，也不为候选平台挤占圆屏菜单空间。
- **操作可用性**：按当前音源实际支持的操作和资源权限展示，不把本地的收藏/播放列表写入能力套用到在线音源。不支持、需要登录、当前资源无权限、临时不可用分别处理；已实现但暂不可用的操作说明原因，不能伪装成空列表或成功结果。
- **按需检查与本地独立**：启动不遍历所有音源进行登录校验、账号刷新或网络探测；只在进入相应在线功能或恢复该来源播放确有需要时检查其会话。切换音源只改变浏览范围，不自动替换队列或停止本地播放；在线故障、登录过期及未接入的候选音源均不阻挡本地库、搜索、收藏、播放列表和已授权文件播放。
- 歌单列表名称为主、歌曲数为辅；缩略图可省略。详情页把名称/数量压成简短摘要，歌曲列表尽早可见；“播放”可以是详情页唯一强调按钮，逐行选歌仍为普通行操作。
- 首次加载显示稳定的“加载中”及返回入口；不展示会闪烁的骨架屏。首次失败与真正空列表使用不同文案。空列表提供符合范围的下一步，例如“返回音乐菜单”，不引导到不存在的添加功能。
- 有缓存时先展示内容与“缓存内容”说明，再在页内静态标记“刷新中”；失败改为“刷新失败，仍显示缓存”。保留列表、选中项和滚动位置，不用全屏错误遮掉歌曲。只有刷新成功才更新数据新鲜度；时间未知时写“更新时间未知”。
- 页尾明确区分“加载更多”“加载失败，重试”“已全部加载”。分页失败重试只作用于失败批次，不跳回顶部，不重复插入已显示歌曲。
- 验收至少包含首次/第二页/末页、1000 首样本、缓存命中/过期/刷新失败、长名称及返回恢复；资源预算由 docs14 判定。

### 6.6 搜索

- 明确分开“搜索本地音乐”与“搜索在线音乐”，页标题和输入提示显示当前范围；本地搜索不需要账号或网络，不因在线错误清空本地结果。避免将范围切换做成圆边上的小标签，使用独立搜索页或一个可点整行入口；保留各自查询与返回位置。
- 输入前展示明确的输入入口和有限历史/提示（仅在产品范围已支持时）；不把空查询显示为“没有结果”。使用设备实际可用的系统输入法，不默认语音或 GMS 服务存在。
- 主动作随步骤变化：输入页为“搜索”，结果页为点选结果。IME 弹出时保持查询可编辑、提交可达；系统返回先退出输入态，再按导航返回。IME 不可用时保留查询/页面并显示“当前输入法不可用”，提供可执行的返回或输入法设置指引。
- 提交后保留查询文本；新查询与旧结果必须清楚区分。可以保留旧内容，但标明“上一查询的结果”，不能在新查询标题下冒充其结果。过时响应不得覆盖最新查询。
- 无结果明确显示对应查询并提供“修改搜索”；在线网络失败保留查询和已得结果，提供“重试”。本地索引尚未完成、来源权限失效和确实无匹配分别提示，不能合成一个“无结果”。同一在线查询的缓存刷新遵守列表规则；多页结果保留滚动位置并去重。
- 测试中文拼音输入、英文长词、emoji、空白查询、快速连续提交、输入法遮挡、无 IME、第二页错误；记录实际输入法名称/版本及测试路径。搜索请求合并与取消规则引用性能/业务文档，不由动画节奏驱动。

### 6.7 错误、不可用与恢复页

- 页面内可恢复错误优先内联；只有没有任何可展示内容或必须重新登录时才进入专用恢复页。结构统一为“发生了什么 → 当前保留了什么 → 下一步”，最多一个最高强调恢复动作。
- 例如“暂时无法联网，仍显示缓存歌单”，主动作“重试”；“登录已过期”，主动作“重新登录”，保留不敏感导航状态；“该歌曲不可播放”，主动作“选择其他歌曲”。是否重试以错误分类为准，不把权限/权益错误伪装成网络问题。
- 禁用操作提供实际原因和禁用语义；不可用能力隐藏或解释，不使用只有变灰却无原因的按钮。错误不能只靠红色、声音或触觉表达。
- 可保留的标题、列表、查询、进度、用户输入与选择均保留；账号切换/退出/安全要求清理的私密内容按正确性与安全规则处理，不能为了“保留内容”展示上一账号数据。
- 不显示 Cookie、密钥、完整资源地址、原始响应或技术栈；可提供脱敏诊断标识。恢复后回原任务，避免把用户反复送回首页。无上限自动重试和连续弹窗不属于恢复设计。

### 6.8 独立本地音乐页与完整管理

**页面层级**：音乐菜单 → 本地音乐 → 歌曲 / 专辑 / 艺人 / 文件夹 / 本地收藏 / 本地播放列表。每类为可滚动整行入口，搜索入口写“搜索本地音乐”；扫描/导入和来源管理在本地页的独立操作页进入。不要挤成六个顶部标签或把全部动作塞进播放页。已有歌曲时以浏览选歌为主；真正空库时唯一强调动作是“添加音乐”，进入实际支持的选择来源/导入步骤，不出现传歌按钮。

| 本地搜索 | 在本地索引中检索曲名、艺人、专辑、文件名；结果注明类型，点击进入对应详情或播放 | 未登录/断网仍可用；扫描部分完成时写“仅搜索已索引内容”；返回保留查询，不把旧查询响应写入新页 |
| 排序 | 单独的“排序”页，显示当前字段与方向；歌曲提供曲名/艺人/专辑/加入时间，其他列表提供适用字段 | 相同键值顺序稳定；缺失值规则一致；记住各列表选择。排序后保持当前歌曲身份及可定位位置，不静默改播放队列；自定义播放列表顺序另行编辑 |
| 本地收藏 | 明确称为“本地收藏”，提供收藏/取消收藏及持久列表；详情操作有文字和选中语义 | 与在线“我喜欢”分开；退出/更换在线账号不清空；取消收藏不删除文件，也不从本地库移除 |

#### 本地播放列表 CRUD 与顺序

- 播放列表首页可新建并查看已有列表；名称为空不保存，同名不能静默覆盖。重命名仅修改列表名，不修改音频标签或文件名。详情可播放、添加歌曲、移除成员和查看不可用成员；零首曲目显示“添加歌曲”，不伪装成加载失败。
- 编辑菜单提供重命名、添加/移除歌曲、调整顺序、删除播放列表，各自进入单任务页面。添加和移除可以逐项或有明确选中数量地批量操作；提交后只显示真正保存的结果，失败保留编辑内容并说明原因。进入/退出编辑不能误切歌。
- 顺序编辑为必需能力：选择一首后进入有足够触控尺寸的“上移”“下移”“移至位置”操作页；首/末项相应按钮禁用且说明原因。不要求拖动、表冠或微小把手；提供“保存顺序”主动作与取消，保存失败保留草稿，成功后重开页面/应用可见持久顺序。退出未保存编辑需明确保留或放弃，不悄悄丢失。
- 删除播放列表确认写出列表名和曲目数，说明“仅删除播放列表，不删除音频文件”；从列表移除歌曲只改变成员关系。取消操作不更改列表；删除失败保留原列表并提供恢复动作。排序视图、持久列表顺序、当前播放队列是不同范围，不能用一个含糊的“清空”操作同时修改。
- 以当前列表发起播放时明确采用当时顺序；之后编辑列表不能无提示地替换当前播放队列。缺失文件保留可识别成员及原因，让用户选择重新授权、重新定位或移除成员，不自动按歌名关联另一份文件。

#### 扫描、导入、部分完成与权限

开始前显示实际选定来源/目录与访问方式，区分“添加外部文件引用”和“导入到应用空间的副本”，说明副本是否占用额外空间；只显示已实现可用的选择方式。重新进入本地页不自动发起全库扫描。任务运行时保留原有库和已完成结果，不用扫描屏阻挡播放控制。

| 状态 | 必需展示与主动作 | 不能出现的误导 |
| --- | --- | --- |
| 未选择来源/未授权 | 说明要访问的来源，主动作“选择音乐来源”或“授权访问”；允许返回本地页 | 让用户先登录在线账号，或默认声称已取得全盘访问 |
| 扫描/导入中 | 展示当前来源、已处理/已加入/跳过/失败数；有可靠总量才显示百分比，否则仅报实际计数；提供“取消扫描/导入” | 编造百分比、循环扫描动画、把未校验的条目当已可播；扫描变化导致正在浏览的行不断跳位 |
| 用户取消/部分完成 | 显示“已取消，保留已完成的 N 项”及确切失败/跳过情况；原有库和已完成导入继续可用，提供“重新扫描” | 标记“扫描完成”或回滚/清空整个库；把尚未扫描的文件当已删除；把半个导入文件显示为完整歌曲；不具备断点能力却显示“继续” |
| 全部完成/完成但有错误 | 分开显示成功、跳过和失败；失败详情按来源和原因查看，重试只作用于适用项目 | 掩盖坏文件、重复项和读取错误；把部分完成标为全部成功 |
| 权限拒绝/撤销/只读 | 指出受影响来源，显示“重新授权”或只读说明；其他来源与已导入副本继续可用 | 清空音乐库、误报零首歌曲、反复弹授权或要求登录 |
| 文件移动/丢失/无法读取 | 保留条目及已知信息，写明原因；实际支持时提供重新定位/重扫，否则提供移除库记录 | 自动关联同名文件、自动删除外部原文件、伪装在线缓冲 |
| 格式/元数据/LRC/封面异常 | 能播放的音频保留；元数据回退文件名，LRC/封面用稳定缺省态；音频不可播时单独说明 | 为修复封面而阻断播放；显示“安装额外解码器”或标签编辑等未在范围内的入口 |
| 空间不足/导入失败 | 保留已完成副本与外部原文件，说明未完成项目；清理未完成临时副本后可重试 | 把残缺副本计作成功、以删原文件腾空间、无依据声称全部回滚 |

进度由实际任务状态驱动，可见页按 docs14 节制展示；不可见/熄屏后停止 UI 刷新，不为显示进度增加 UI 计时器。扫描业务是否继续、取消完成边界和任务恢复政策引用 docs17，并记录其实际状态；停止 UI 刷新不等于声称任务已取消。

#### 文件操作的对象和删除确认

| 操作名称 | 实际影响 | 必须说明与核验 |
| --- | --- | --- |
| 从播放列表移除 / 取消收藏 | 仅修改相应列表或收藏关系 | 不删除音乐库条目或音频文件；返回后反映真实保存结果 |
| 从本地库移除 | 移除库记录，保留物理文件；相关引用按 docs17 规则标记或更新 | 明说“不会删除文件”；提示再次扫描可能重新发现，不能冒充物理删除成功 |
| 移除音乐来源 | 停止该来源的扫描/展示，关联条目按 docs17 标记来源不可达；保留外部原文件和本地收藏/播放列表引用 | 说明影响范围与重新添加/授权的恢复路径；不附带清空收藏或删除文件选项 |
| 删除导入副本 | 仅删除应用持有的完整导入副本，并同步其本地引用状态 | 确认页标题写“删除导入副本”，显示名称、数量和副本来源，明确“外部原文件保留”；不得捆绑原文件删除 |

导入副本删除确认页只有一个明确的破坏性主动作和可达取消，不用含糊的“确定”，也不提供“同时删除源文件”选项。长文件名/路径可滚动查看，48dp/56dp 触控及大字体要求照常适用。涉及正在播放的副本时先说明将停止该曲，完成后同步播放状态；确认前取消保持文件和列表不变。批量操作仅限明确选中的应用导入副本，逐项报告成功/失败/未执行；部分失败不得写“已全部删除”，已删除部分也不得假称撤销。确认页退出、存储不可写和副本删除失败均须验收；任何批量入口都不能接受外部原文件作为删除对象。

## 7. 状态覆盖与反馈

| 状态 | 必需的视觉与交互表现 | 必须检查的失败方式 |
| --- | --- | --- |
| 默认 | 稳定尺寸、明确主动作、数据来源清楚 | 封面压过主键；多个同强度主动作 |
| 按下/焦点/选中 | 固定几何的颜色变化或可辨轮廓；选中同时有文字/符号 | 靠缩放推动布局、焦点环被圆切掉、选中只有颜色 |
| 解析/缓冲/加载 | 静态状态词，目标曲目/已有内容保留；可取消时入口可达 | 无限旋转图形、旧封面冒充新曲、按钮与真实状态相反 |
| 禁用 | 禁用语义、可读原因；不缩小目标 | 仍触发请求、只有低透明度无法辨认 |
| 空 | 区分真实无数据、无查询、未登录；给可执行下一步 | 把失败当空、摆出未实现的操作 |
| 缓存刷新 | 标注缓存/刷新；成功后更新，失败保留内容与位置 | 全屏替换、数据清空、虚假的“刚刚更新” |
| 扫描/导入部分完成或取消 | 保留原有库及已完成结果，分别说明实际完成、失败、跳过、未完成项目 | 假百分比、清空库、取消后显示全部成功、把半文件当可播 |
| 本地权限失效/文件丢失 | 显示受影响来源与可执行恢复路径，其他有效内容可用 | 当成未登录、静默串配同名文件、缺图或坏 LRC 阻断音频 |
| 列表编辑/重排/保存失败 | 区分草稿与已保存顺序，主动作明确，失败保留草稿 | 用排序视图冒充持久重排；保存失败却关闭编辑并显示成功 |
| 移除记录/来源、删除副本及部分失败 | 明确只影响索引/来源/列表或应用导入副本，外部原文件保持；逐项显示实际结果 | 暴露外部原文件删除入口、共用含糊“删除”、取消后仍删、把部分失败当全成功 |
| 可恢复错误 | 说明原因、保留上下文、一个明确恢复动作 | 错误弹层盖住播放；重试生成重复操作 |
| 不可恢复/权限/登录失效 | 给实际可行路径，避免无效重试 | 无限重试、泄露凭据、显示其他账号缓存 |
| 返回/重建/重新可见 | 恢复同一业务状态及位置，再显示稳定界面 | 从头动画、重放历史过渡、两个播放状态不一致 |

所有适用组件都覆盖这些状态；某状态不适用必须写出具体原因，不得以“截图未展示”为理由省略。

## 8. 动效、生命周期与性能约束

1. 默认使用无动画状态更新。需要交代位置关系时可采用一次短淡入或小距离位移，初始设计建议 120ms、最长 180ms，位移不超过 8dp；这些是待验证的过渡设计参数，**不是 docs14 的性能测量预算**，其约束更严时服从 docs14。页面滑动手势本身跟随输入，结束后不叠加弹簧或回弹装饰。
2. 连续输入合并/中止过时过渡，最后一次意图优先；不能排队播放动效来追赶业务状态。不使用常驻旋转封面、呼吸灯、粒子、音谱、循环 shimmer、重型模糊、发光、默认跑马灯或加载动画。缓冲/加载用静态文字和必要的业务状态更新即可。
3. 尊重系统减少动画/关闭动画设置及可用的应用减少动态效果选项；具体系统入口以设备为准 [R7]。减少动态效果模式下直接切换，保留文字/图标反馈；不能靠动画完成回调才提交播放或导航。若系统没有该入口，记录缺失并验证应用内静态模式，不宣称系统适配已通过。
4. **页面不可见或屏幕关闭时，停止所有 UI 定时器、动画时钟、封面轮换、进度插值和歌词 UI 跟随。** 相邻但不可见分页同样停止；不只检查 Activity 是否仍存在。屏幕关闭不得保留用于绘制的定时任务或反复唤醒视图。媒体播放服务按业务运行，不把音频时钟与 UI 时钟混为一谈。
5. 重新可见时从当前会话获取一次快照，再按 docs14 恢复必要的前台刷新；不回放隐藏期间积累的 tick、滚动或重试。登录页面退出后的业务轮询取消另验，不能只停动画却继续无用请求。
6. 不强制要求或承诺 60fps，也不为追求某个帧率保持常亮。帧时序、刷新率、卡顿、输入反馈、内存、CPU/GPU、耗电及图片成本按 docs14 的设备条件与统计口径判定；高刷新模拟器上的录屏不证明手表流畅。
7. 动效、阴影或封面效果引发回归时，先移除其额外成本并以静态层级完成设计；不能用回归免责换“高级感”，也不能把未排齐文字、缺失反馈和难看的占位留作性能优化成果。新增效果必须同时交出视觉收益、相应性能证据与可读性评审。

### 9.2 证据链与操作路径

每份记录绑定同一候选产物的 source SHA、实际 build SHA、云端 run ID/attempt、APK SHA-256、版本、签名指纹。所有截图、短录屏、状态日志和该候选的 docs14 性能记录必须能回溯到这个 APK；基线对照可使用另一个明确标识的基线 APK，但不能用旧版性能数据为新版界面担保。

必须保留：

1. **截图组**：每个核心页面的实际 Watch X2 截图；默认、按下（可由录屏帧补证）、缓冲、空、错误、禁用、缓存刷新及大字体/长文本的适用状态。记录尺寸、字体、数据集、业务状态和文件编号，不能只交正常短标题的精修图。
2. **短录屏组**：分别记录在线路径“登录/扫码 → 列表/搜索 → 点歌 → 播放/暂停 → 队列 → 歌词”，和未登录/断网的本地路径“本地音乐 → 选择来源/扫描 → 分类/搜索 → 点歌 → 本地 LRC/缺省态 → 收藏 → 创建并编辑/重排播放列表”。另录扫描取消/部分完成、权限恢复、移除索引/来源后原文件保留、导入副本删除确认与取消、错误恢复、缓存刷新失败和大字体滚动。单段建议约 15–30 秒，按任务拆段；不要快放、删去等待或拼接成看似无缝的性能证据。真实扫码过程可用外部拍摄补充，确保脱敏。
3. **实际操作记录**：边缘目标点击、系统返回、首尾项可达、IME、辅助阅读、二维码扫描、熄屏再亮屏；另验未登录本地播放、退出/换账号后本地资料保留、列表保存/重排后重新打开持久性、扫描取消和文件删除的实际后果。注明操作次数和每次结果，不把主观“很顺滑”当计时或误触测量，不仅凭成功提示判断文件是否已删除。
4. **性能回归记录**：直接关联 docs14 的指标编号/规范版本、基线与候选产物、同条件重复观测、原始 trace/报告和通过理由。至少关联本次受影响的启动、控制、列表/图片、歌词、内存与后台/熄屏 UI 活动；本地另关联扫描/导入与播放并行、索引查询/排序/分页、收藏/播放列表编辑持久化和取消响应。完整必需项由 docs14 决定，不在本文件另设数值预算。无设备、工具失败、样本不足均填未测/证据不足，禁止填 0 或通过。
5. **可读性与功能记录**：链接 docs16 对应评审、docs06 相关用例、T-23–T-31 本地专项、docs17 功能与边界验证结果及未解决问题。使用界面模板中的对应表关联，不将界面用例编号当成 docs06 或 docs17 编号。不同构建或不同固件的材料分开记录，不拼成一次完整通过。

采集截图/录屏会改变运行条件。截图与性能测量可分时进行，但必须同一候选 APK、可比较状态和明确条件；按 docs14 使用未录屏的测量轮次，单列录屏开销及测量工具开销。演示视频只作动态行为证据，不替代性能报告。
