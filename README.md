# MeloX Watch

**面向 Android 智能手表的本地与在线音乐 App。** 产品不绑定厂商或型号，不强制依赖 Google 服务或手机伴侣。根据实际系统能力、窗口尺寸、圆形/方形屏幕和输入方式适配；Wear OS 专属能力另行验证。

用户现有的 OPPO Watch X2 是首个实机基准，**不是支持范围白名单**。当前没有应用或任何机型的验收成绩，兼容清单将分别记录“设计目标、模拟验证、实机通过”，不以一个型号的结果代表全部手表。

**当前阶段：全量本地规划已整合，CI-01–04工作流维护及政策接线已验证，Android 应用暂未实施。** 探针和业务代码等待用户明确恢复范围。Issue #15已将隔离编译/签名与候选/同包发布入口维护到两个长期分支，云端政策正反例及无Android候选拒绝有证据；真实APK链路仍未验收。精确记录见[建设记录](docs/ci/CI-01–04建设记录.md)和[实际状态](docs/13-仓库状态.md)。当前私有套餐不支持强制分支/tag保护，没有应用工程、APK或实机验收结果。

仓库保持私有，目前只有 OnlineMo 有写权限。已记录的 GitHub rulesets GET 返回 **403**，需要升级 GitHub Pro 或改为公开才能启用所需保护；当前没有强制分支/tag 保护。CI 无法单独阻止管理员直接推送，所有者始终可以重新配置规则。

**公开后必做：执行 GOV-PUBLIC-01，立即为 main/contribution 配置必需 PR、检查、禁止强推/删除和管理员约束，核验后再发版。** 具体开关与证据清单见 [仓库治理第 6 节](docs/10-仓库治理与发布.md)；当前只记录要求，不提前公开。

## 执行入口

正式开工先读 [21 全量需求](docs/21-本地播放器全量需求整合.md)，再读 [20 终审与开工清单](docs/20-终审结论与开工清单.md)，按 [05 任务依赖](docs/05-开发阶段与任务清单.md) 执行。本轮推进规划整合与已授权开发前置，应用建设等待用户明确恢复范围。

终审补入的CI改造已完成工作流维护：编译与签名隔离、无发布副作用的候选入口、验收同一APK后发布，以及版本/同步政策。**入口部署不等于实际APK链路已验收**；当前prepare-candidate因无Android工程必须拒绝，真实发版仍需CI-01–04的产物验收与10/12全部门槛。不要为拿APK而提前勾选发布门槛或回退旧单阶段流程。

不再估算工期、人日、工作量或代码量。05只维护任务、依赖、实际进展与验收；首次公开门槛包含全部128项，不沿用旧小型本地模块范围。

## 必须保持的约束

- 性能第一、界面美观第二，可读性必须达标；正确性、隐私与可访问操作不可交换。预算和测量口径只看14，界面看15，代码/注释看16。
- 首版完整本地音乐＋网易云＋用户自填Meting；离线核心无账号、无互联网可用，显式联网辅助不影响独立播放；在线60分钟/本地120分钟熄屏验证。在线持久下载属于P4，未来音源不预定平台或登录方式。
- 只在云端编译/测试/lint，本地编辑与设备验证。原两个MeloX和新增协议参考都固定完整SHA，不自动追随上游。
- 普通贡献者不得改版本；所有者版本提案仍需校验。所有PR不得改workflows/actions，改动通过Issue＋所有者维护；提交使用本人noreply，禁止AI协作者和Co-authored-by。
- 按10生成冻结候选：`versionCode=max(候选源main完整提交数+1, 已发布最大code+1)`；验收后网页发布**原快照和原APK**，不重编译、不重签、不回写开发分支、不增加发布分支。
- 公开与发版分别批准；公开后立即执行GOV-PUBLIC-01并核验。当前套餐限制及真实已执行检查只看13，不能把计划当成已启用。
- 正式与Debug证书隔离，密钥/真实邮箱/本地快照不进入应用仓库。用户单独授权的证书恢复仓库永久私有；本文不包含其地址或秘密。

候选、公开门槛及你的职责见 [12](docs/12-首个公开版本与责任清单.md)。本地开工提示词已随终审同步，继续被Git忽略；仓库中的规范才是长期依据。
