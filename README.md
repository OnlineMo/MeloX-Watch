# MeloX Watch

**面向 Android 智能手表的本地与在线音乐 App。** 产品不绑定厂商或型号，不强制依赖 Google 服务或手机伴侣。根据实际系统能力、窗口尺寸、圆形/方形屏幕和输入方式适配；Wear OS 专属能力另行验证。

OPPO Watch X2 作为首个真机测试基准。兼容性按实际 API/ABI、窗口形状与输入能力验证，清单分别记录设计目标、模拟验证和真机验收结果；其他设备的支持结论以对应测试为准。

**当前阶段：公开开发中。** 已有内部云端Debug基线，完整本地播放器、在线功能和手机配套继续建设；首个完整预发布版及真机验收尚未完成。精确记录见[实际状态](docs/13-仓库状态.md)。

根据隐私审查与公开治理记录，开发仓库已公开。main/contribution 的必需PR、GitHub Actions来源绑定检查、strict和管理员约束，以及v*禁止更新/删除，均已通过实际配置读回；只有OnlineMo有写权限。普通PR验证及非敏感证据见[GOV-PUBLIC-01记录](docs/governance/GOV-PUBLIC-01-2026-11-22.md)。

**开发仓库公开与首个预发布版发布分别验收。** 公开没有批准Release；首版仍须完成全部128项/256AC、双端同候选与真机验收，再由所有者批准具体候选。保护要求见[仓库治理第6节](docs/10-仓库治理与发布.md)。

## 执行入口

先读 [21 全量需求](docs/21-本地播放器全量需求整合.md)，再读 [20 终审与开工清单](docs/20-终审结论与开工清单.md)，按 [05 任务依赖](docs/05-开发阶段与任务清单.md) 执行。根据全量需求和任务依赖，持续完成应用实现、云端验证与设备验收；最终验收和具体候选的发布批准独立记录。

终审补入的CI改造已完成工作流维护：编译与签名隔离、无发布副作用的候选入口、验收同一APK后发布，以及版本/同步政策。**入口部署不等于实际APK链路已验收**；首次依赖资料在无秘密PR中生成并审阅，随后严格验证构建。真实候选与发版仍需CI-01–04的产物验收与10/12全部门槛，不能提前勾选或回退旧单阶段流程。

不再估算工期、人日、工作量或代码量。05只维护任务、依赖、实际进展与验收；首次预发布门槛包含全部128项，不沿用旧小型本地模块范围。

## 必须保持的约束

- 性能第一、界面美观第二，可读性必须达标；正确性、隐私与可访问操作不可交换。预算和测量口径只看14，界面看15，代码/注释看16。
- 首版完整本地音乐＋网易云＋自行配置的Meting；Meting默认关闭，无内置公共端点。离线核心无账号、无互联网可用，显式联网辅助不影响独立播放；在线60分钟/本地120分钟熄屏验证。在线持久下载属于P4，未来音源不预定平台或登录方式。
- 只在云端编译/测试/lint，本地编辑与设备验证。原两个MeloX和新增协议参考都固定完整SHA，不自动追随上游。
- 普通贡献者不得改版本；所有者版本提案仍需校验。所有PR不得改workflows/actions，改动通过Issue＋所有者维护；提交使用本人noreply，禁止AI协作者和Co-authored-by。
- 按10生成冻结候选：`versionCode=max(候选源main完整提交数+1, 已发布最大code+1)`；验收后网页发布**原快照和原APK**，不重编译、不重签、不回写开发分支、不增加发布分支。
- 公开与发版分别批准；公开后立即执行GOV-PUBLIC-01并核验。当前套餐限制及真实已执行检查只看13，不能把计划当成已启用。
- 正式与Debug证书隔离，密钥/真实邮箱/本地快照不进入应用仓库。根据签名恢复方案，证书恢复仓库永久私有；恢复地址及秘密只保留在私有恢复材料中。

候选、首版发布门槛及维护职责见 [12](docs/12-首个公开版本与责任清单.md)。本地开工提示词已随终审同步，继续被Git忽略；仓库中的规范是长期依据。
